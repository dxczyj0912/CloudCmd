# 真实环境验收

练习平台的模拟终端只验证命令教学逻辑、步骤顺序和可判定输出；它不代表真实网络、权限、云资源、费用或副作用已经验证。涉及这些边界时，按本页建立隔离环境并提交证据清单。

## 验收边界

- 网络连通性、DNS、TLS、代理和防火墙必须在真实网络中验证。
- Linux 权限、systemd、Docker、Kubernetes、数据库备份恢复和云 CLI 要分别验收，不能用一条“部署成功”替代。
- 云资源创建、弹性 IP、磁盘、负载均衡和数据库实例可能产生费用；使用测试账号、最小规格、隔离项目，并在记录中写清资源 ID 和清理方式。
- 危险命令必须有变更窗口、测试账号、快照或回滚方案。没有回滚路径的命令只做只读验证。
- 真实验收不写入模拟器判题，也不把真实资源 ID、账号、密码、AK/SK、token、kubeconfig 或私钥提交到仓库。

## 证据要求

复制 [真实环境验收模板](真实环境验收模板.json)，填写 `environment` 和 `evidence`，然后运行：

```bash
node tools/real-lab-check.js --manifest=docs/真实环境验收模板.json
```

每条证据至少包含唯一 `id`、验收领域 `area`、实际命令 `command`、关键结果 `result`、UTC 时间 `checkedAt`、`passed`/`failed`/`blocked` 状态。`artifact` 只能指向仓库内的相对路径；截图、脱敏日志和报告放在仓库外或经过审核后再放入 `docs/evidence/`。

建议按以下领域分别记录：

| 领域 | 重点检查 | 必须留下的证据 |
| --- | --- | --- |
| network | DNS、端口、HTTP/TLS、路由、防火墙 | 目标、来源网络、命令、退出码、响应摘要 |
| permission | 用户、属主、权限、sudo、SELinux | 脱敏后的权限输出、变更前后状态、回滚方式 |
| docker | 镜像、网络、卷、Compose、日志 | 镜像 digest、容器状态、卷和网络清理记录 |
| kubernetes | apply、调度、Service、Ingress、回滚 | 集群版本、命名空间、资源状态、rollout/rollback 结果 |
| database | 备份、恢复、复制、权限 | 数据库版本、备份校验、恢复目标、行数或校验和 |
| cloud | 计划、创建、查询、删除、费用 | 项目/区域、资源 ID、请求 ID、清理结果 |

验收清单只做格式和敏感信息检查，绝不会执行 `command` 字段。执行命令前仍需人工确认目标、权限、费用和副作用；`passed` 只表示这条证据在指定环境通过，不表示所有环境都安全。
