> **3. 过程中发现"难度"必须有两个口径 —— 这是本轮最重要的认知修正**
> v3.6 的 `levelOf` 取一节课引用命令的**最高** level。用它判"有没有入口"时，
> 我新写的 8 节入口课**全部被判成 L2/L3**（因为它们"从 L1 起步、讲到 L2/L3"）——
> 于是"这个分类没有入门课"的结论**永远成立**，补了课也看不出来。
> 修正：新增 `entryLevelOf`（取**最低** level）。
> **`levelOf` 回答"这节课最深讲到哪"（显示难度徽章）；`entryLevelOf` 回答"从哪个水平能开始学"（判有没有入口）。**
> 一节课完全可以"从 L1 起步讲到 L3"，那种课对新手是能进的 —— **判入口看起点，不看终点**。
> 同时把 kvm / security 两节的步骤顺序调成"最简单的排在最前"（入口课第一屏不该是进阶命令）。

> 1. **算术展开 `$(( ))` 完全不可用** → 可用。根因是 `maskBlocks` 把 `$((` 内层的 `(` 屏蔽成了
>    NUL，下游再也认不出这是算术展开，把它当"命令替换，命令是 `(2+3)`"去执行 —— 于是
>    `echo $((2+3))` 静默输出空行、`i=$((i+1))` 把计数器清空。→ §6.5 第 40 条
> 2. **`[ ]` 数字比较恒真/恒假** → 正确。两个独立缺陷：`testTokenize` 的词扫描不把 `-` 当边界，
>    argv 到达时已经是 `['1 -lt 2']` 一个词；更严重的是双目操作数**取反了**
>    （`a = toks[p+1]` 拿到的是运算符），于是 `[ "$A" = web ]` 恒假、`[ 1 -lt 2 ]` 恒真。→ 第 41 条
> 3. **`A && B || C` 里 A 失败就 `break` 整行** → A 失败只跳过 B、继续判 C。
>    原先 `false && echo yes || echo no` **什么都不打印**，退出码还看着正常。→ 第 42 条
> 4. **`while read … done < file` 循环体一次都不执行** → 可用。根因是执行器在每个命令前
>    无条件把继承来的 stdin 抹成 `null`，`read` 拿到空流立刻返回 1。→ 第 43 条
> 5. **`for i in $(seq 1 3)` 迭代出 `$(seq`/`1`/`3)`** → 可用（词表里的命令替换先跑，再按 IFS 切词）。→ 第 44 条
> 6. **`case` 把待匹配的词当命令执行**（`bash: abc: command not found`）→ 可用；并修掉
>    `ctrlParseCase` 吞掉 `esac` 之后所有语句的问题（循环体里嵌 case 曾是空的）。→ 第 45、46 条
> 7. **循环体里不能嵌 `if`**（`bash: if: command not found`）→ 可用（循环体按语句数组递归解析控制流）。→ 第 47 条
> 8. **管道接控制流不可用**（`… | while read` 报 `while: command not found`）→ 可用。→ 第 48 条
> 9. **管道里的循环不在子 shell 里** → 按真 shell 语义隔离变量表。这一条是**教材一致性问题**：
>    站内 `sh-while-until`/`sh-pipe-cmdsub`/`sh-read` 三个条目都写着
>    "`cat f | while read x; do n=$((n+1)); done; echo $n` 输出 0"，而引擎当时输出 3。→ 第 49 条
> 10. **`ls | wc -l` 恒等于 1** → 按真 `ls` 的规矩区分"终端按列 / 管道一行一个"。→ 第 50 条
> 11. **`> 文件 2>&1` 只写 stdout、stderr 还在屏幕上**；**`> out 2> err` 会把 `>` 当参数传给命令** → 都正确了（多重定向按顺序应用）。→ 第 51、52 条
> 12. **`X=$(cmd | awk …)` 报"命令替换括号不配对"、变量静默为空** → 可用；
>     同时修掉 `${VAR:?}` 打印 `undefined`、`${VAR:=}` 写不回变量表、`N=$(… | wc -l)` 被前导空格切成空。→ 第 53~55 条
> 13. **shell 课程从 5 节补到 7 节**：第 2 课改用 `while IFS= read -r`（原先因引擎不支持而退化成了
>     遍历字面量列表），第 4 课补上 `${VAR:?}` 真校验，第 5 课补上 `2>&1` 顺序的正反两个实验，
>     **新增第 6 课「管道里的 while 数不出数：子 shell 陷阱」**与
>     **第 7 课「同一个脚本服务多个场景：用 case 分派动作」**。
>     第 1 课那个会真删 `/data/backup/www-2024-03-16.tar.gz`（termfs 跨会话共享）的步骤
>     改成了"先在 /tmp 副本上走通删除"。→ 课程 77 → **79 节**，步骤 310 → **326 步**

## 1. 项目概述

### 1.1 一句话定位

一个**零依赖、离线可用、可搜索**的云计算命令速查与学习网站，把云计算全栈会用到的指令按知识体系整理成一本能"点开就能用、照着就能敲"的手册。

### 1.2 为什么做这个

学习云计算的人普遍面临三个痛点：

| 痛点 | 现状 | 本项目的解法 |
| --- | --- | --- |
| 命令散落各处 | 官方文档英文、博客残缺、收藏夹一堆链接 | 一个站点内**全量归类**，中文说明 + 官方文档直达链接 |
| 记不住参数 | 靠搜索引擎，找到的多是过时答案 | 每个命令给出**真实可跑的示例**与参数表，支持一键复制 |
| 不知学习顺序 | 不知道该先学 Linux 还是 K8s | 提供**学习路线图**，命令带难度分级与所属知识域 |

### 1.3 目标用户

1. **在校学生 / 转行者**：零基础入门云计算，需要一条清晰的命令学习路径。
2. **初级运维 / 后端开发**：日常查参数、查语法，替代低效的搜索引擎。
3. **华为云使用者（首要人群）**：以华为云 ECS/OBS/CCE 为主力工作平台，需要 KooCLI 与容器服务的实操命令。
4. **备考者**：华为 HCIA/HCIP-Cloud、CKA/CKS、RHCE 等认证的实操命令复习。
5. **面试准备者**：按知识域快速过一遍高频命令与原理要点。

### 1.4 设计原则（贯穿全部决策）

- **P1 零构建、零依赖**：不引入 npm 包、不引入框架。双击 `index.html` 就能用，也能直接扔到 Nginx/OSS/GitHub Pages。
- **P2 离线优先**：全部命令数据本地化，断网可用（这是与"搜索引擎"竞争的唯一理由）。
- **P3 内容即数据**：命令全部结构化存储，页面只是渲染层，方便后续加导出/统计/测验。
- **P4 中文优先、术语对照**：说明用中文，术语保留英文原名，避免翻译歧义。
- **P5 可复制即正义**：任何命令 1 次点击即可复制，代码块高亮关键参数。
- **P6 渐进增强**：无 JS 时至少能看到内容（数据用 `<script>` 注入 + 首屏静态兜底）。

### 1.5 非目标（明确不做，防止范围膨胀）

- ❌ 不做用户登录、不做后端服务、不做数据库。
- ❌ 不做在线实验环境（不集成 Web Terminal / 沙箱容器）。
- ❌ 不做视频课程、不做付费体系。
- ❌ 不做命令的逐参数穷举（`man` 手册的活我们不抢），只收录**实际高频使用的参数**，低频参数给官方链接。

### 2.3 关键交互细节

- 搜索：支持中文与英文混合；匹配命令名时权重最高，其次中文说明，最后示例。
- 复制：使用 `navigator.clipboard`，`file://` 协议下自动降级为 `document.execCommand('copy')`（关键！否则本地双击打开无法复制）。
- 进度：`localStorage` key = `cloudcmd.progress.v1`，存 `{ mastered: [id...], favorites: [id...], theme: 'dark'|'light'|'auto' }`。
- 路由：`location.hash` 驱动，格式 `#/c/<categoryId>`、`#/cmd/<commandId>`、`#/roadmap`、`#/search?q=xxx`，刷新后位置不丢。

## 3. 技术方案

### 3.1 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 结构 | 原生 HTML5 | 无构建，直接可读 |
| 样式 | 原生 CSS（CSS 变量 + Flex/Grid） | 主题切换靠变量，无预处理器依赖 |
| 逻辑 | 原生 JavaScript（ES2018+，无模块化） | 避免 `file://` 下 ES Module 的 CORS 限制 |
| 数据 | `window.CC_DATA` 全局注册表 + 独立 `data/*.js` | 双击可开，也方便按分类维护 |
| 字体 | 系统字体栈 + 等宽栈 | 不联网加载字体，保证离线 |
| 图标 | 内联 SVG / Emoji | 不引图标库 |
| 依赖 | **0 个 npm 包** | 见原则 P1 |

> **为什么不用 ES Module / 不用 Vite**：本项目第一使用场景是"本地双击 `index.html` 打开"。`file://` 协议下 `import` 会被 CORS 拦截，`fetch('data/x.json')` 同样被拦。因此数据用**传统 `<script>` 标签**注入全局变量，逻辑用 IIFE 包裹。这是刻意选择，不是技术债。

**KooCLI（`hcloud`）关键事实**（Phase 2 写 cloud-cli.js 时严格遵守）：

```bash
# 安装（Linux，一条命令）
curl -sSL https://hwcloudcli.obs.cn-north-1.myhuaweicloud.com/cli/latest/hcloud_install.sh -o hcloud_install.sh && bash hcloud_install.sh

# 交互式配置 AK/SK（首次必做）
hcloud configure init

# 或用命令直接配置
hcloud configure set --cli-profile=default --cli-access-key=<AK> --cli-secret-key=<SK> --cli-region=cn-north-4

# 查看当前配置 / 切换 profile
hcloud configure list
hcloud configure list --cli-profile=<名字>

# 命令形态：hcloud <服务名(大写/小写均可)> <操作名>
hcloud ECS ListServersDetails --cli-region=cn-north-4 --project_id=<项目ID>
hcloud ECS NovaShowServer --server_id=<云服务器ID>
hcloud VPC ListVpcs

# 查询某服务有哪些操作、某操作有哪些参数（自省能力，非常关键）
hcloud ECS --help
hcloud ECS ListServersDetails --help

# 输出格式化
hcloud ECS ListServersDetails --cli-output=json
hcloud ECS ListServersDetails --cli-output=table
hcloud ECS ListServersDetails --cli-query="servers[*].name"
hcloud ECS ListServersDetails --cli-jsonInput=./input.json    # 复杂参数用 JSON 文件传入
```

**写作红线（华为云特有）**：

1. **区域标识用真实 region**：`cn-north-4`（北京四）、`cn-east-3`（上海一）、`cn-south-1`（广州）等，不要编造。
2. **`project_id` 与 `region` 是高频坑**：KooCLI 报错多数源于二者不匹配，示例中必须带上或提示先 `hcloud configure`。
3. **AK/SK 绝不硬编码在示例里**：统一写 `<你的AK>`，并在 notes 中强调"不要提交到 Git、建议用临时 AK 或 IAM 子用户"。
4. **OBS 有两种入口**：`hcloud OBS ...`（KooCLI 封装）与 `obsutil`（专用工具），两者语法不同，**不能混淆**，写示例时明确标注用哪个。
5. **CCE 与标准 K8s 的差异**：CCE 集群的 kubeconfig 从控制台下载；`kubectl` 语法完全一致，因此 K8s 分类**不必为华为云写特殊命令**，只需在"获取 kubeconfig"环节给 CCE 的操作路径。
6. **无法核实的命令宁可不写**：华为云 API 迭代快，凡不确定的操作名一律去掉，只保留能查证的。

### 3.10 手机版（可看可练）

**手机上不是"把桌面布局堆起来"，而是换一种分工。**

桌面是「左终端 42% + 右讲义 58%」并排，两者始终同时可见。手机上如果照搬堆叠，
终端会吃掉固定高度、讲义只剩几十像素 —— **看得见终端、看不见讲义**。
而手机上的真实动作是「看一步 → 点运行 → 看输出」，两者必须同时在场。

所以手机版（`≤760px`）的布局是：

```
┌─────────────────────┐
│ 顶栏（紧凑）          │
├─────────────────────┤
│ 讲义（占满剩余空间）   │ ← flex:1，可滚动，正文可视高度 ≥150px
│  步骤 / 运行 / 复制    │
├─────────────────────┤
│ 终端（贴底，34dvh）    │ ← 点「运行」立刻能看到输出
│ [↑][↓][|][-][/][~]…  │ ← 快捷键条，横向可滑
│ root@cloudcmd-lab01# │
└─────────────────────┘
```

| 手机上独有的问题 | 处理方式 |
| --- | --- |
| `\|` `~` `$` `*` 藏在符号键盘里，方向键干脆没有 | **快捷键条**：13 个按钮，横向可滑；点 `\|` 插到光标处（不是简单追加，手机上改一个字符很贵）；`↑`/`↓` 复用命令历史，与物理键盘同一份逻辑 |
| 软键盘弹出会盖住半个屏幕（iOS 上 `innerHeight` 还不跟着变） | 用 `visualViewport` 的 `resize`/`scroll` 写 `--vvh`，`body` 高度跟着收缩，输入行自然浮在键盘之上。**必须同时清掉基础规则里的 `min-height:100vh`**，否则 min-height 会压过 height，高度根本收不回去 |
| 聚焦屏幕外的隐藏输入框会让画面先跳一下 | 桌面端隐藏输入框放在 `-9999px`；手机上改放到终端自己底部（本来就在可视区内） |
| iOS 聚焦 <16px 的输入框会自动放大整页 | 手机端所有 `input/select/textarea`（含 `#search-input` 这种 ID 选择器）≥16px |
| 手指按不准 | 「运行 / 复制」26→40px、快捷键 38px、收藏星标 30→42px、导航项 ≥46px |
| 刘海屏 / Home 指示条 | `viewport-fit=cover` + `env(safe-area-inset-*)` |
| 双击缩放 300ms 延迟、滚动橡皮筋 | `touch-action:manipulation` + `overscroll-behavior:contain` |
| 讲义面板看着够高，正文却被挤没 | 头图在手机上瘦身（副标题隐藏，92→42px）、步骤条改单行横滑（85→43px）、终端让出高度（40→34dvh）。**断言直接量正文可视高度**，不量面板高度 |

**自动化验证**（`tools/lab-check.js` 第 [7][8] 段，共 25 条断言，全部用真实测量）：
用 CDP 的 `Emulation.setDeviceMetricsOverride` 模拟 **375×667**（iPhone SE），断言讲义正文 ≥150px、
终端贴底、两者同屏、快捷键真能插入字符、`↑` 真能取回上一条、全屏终端能切能回、
软键盘弹出时 body 收缩且终端不被盖住、主站抽屉默认收起、分类页 → 练习列表 → 平台深链整条链路可点。

> **一条方法论**：手机版是"截图先发现问题、DOM 测量再定位原因"。
> 纯靠测量会漏掉"看着就是不对"的问题（第一版讲义正文只剩 49px，所有阈值断言当时都是绿的，
> 因为它量的是面板高度而不是正文高度）；纯靠截图又会误判（无头浏览器的窗口尺寸 ≠ 视口尺寸）。
> 正确顺序是：**截图发现异常 → 量出具体数字 → 写一条能卡住它的断言**。

### 3.11 每日一练（`#/drill`）

**这不是"背命令名"。** 单词是「符号 ↔ 含义」的映射，记住就等于学会；命令不是。

> 「`du` → 查看目录占用」这种卡，刷三遍就永远不会忘 —— 但它**不会让你在磁盘满的时候想起 `du -sh *`**。
> 真正要练的是**判断**：什么现象该用哪条命令、为什么不是旁边那条、参数差在哪。

所以三种卡型的正面**一律不是命令名**：

| kind | 正面 | 背面 |
| --- | --- | --- |
| `diagnose`（现象 → 命令） | 用用户的话描述症状（"磁盘满了，可你把目录翻了一遍，`du` 加起来远远不到分区大小"） | 该敲什么 + **判据** + 反向排除 |
| `distinguish`（辨析） | 一组容易搞混的用法（"`df -h` 显示还有 20G，但新建文件报 `no space left`"） | 分界在哪、什么时候用哪个 |
| `syntax`（参数填空） | 挖了空的命令 | 答案 + 为什么是这个参数 |

**★ 相对 Anki / 百词斩 的唯一优势：背面能「送进终端跑一遍」。**
背单词 app 只能给你"释义"，这里能把命令送进模拟终端看到**真实输出**。
凡是引擎实现过的命令，卡片都必须填 `run`。技术上是复用主站已有的**临时 Shell 面板**
（`CC_APP.runInShell()` → `CC_TERM.runInPanel()`），所以卡片里连着跑几条命令时状态是连续的（`cd` 会保留）。

**算法**：简化版 SM-2。每张卡记 `{ease, interval, due, reps, lapses, last}`，
三档反馈 `不会 / 模糊 / 会了`；`ease` 夹在 `[1.3, 2.8]`，间隔上限 180 天。
`due` / `last` 用 **`YYYYMMDD` 整数** —— 跨天比较不涉及时区，也不用 `Date` 运算。

**队列怎么排**（这是"每日一练"好不好用的关键）：

```
1. 到期的卡（due <= 今天），按到期先后
2. 不够就补：收藏的 > 练习课里做错的分类 > 从没见过的
3. 新卡按 level 升序，并且**按分类轮转** —— 否则一上来就是十几张 Linux 基础，很劝退
4. 一天最多 12 张。宁可少而每天来，不要一次刷到吐
```

**⚠️ 一条刻意的设计：卡片不产生"总进度"。**
页面只显示「今天做了几张 + 连续天数 + 卡库见过多少」，**没有"总掌握率"这种像成绩单的数字**。
刷 200 张卡的心理满足感，和真的会在服务器上排障，是两件事 ——
UI 上必须把话说清楚：**真实进度以练习课的完成度为准，卡片只是帮你记住的辅助入口**。

**状态存哪**：只有间隔重复进度落 `localStorage`（`cloudcmd.v1` 里的 `srs` 与 `drill` 两个桶）；
"今天练到第几张"是**一次会话**的状态（放在闭包里，刷新即重置）——
明天进来应该是新的一轮，而不是接着昨天的第 7 张。

**卡片的快捷键**：`空格` / `Enter` 翻面，`1` `2` `3` 对应 `不会 / 模糊 / 会了`（翻面前打分键不生效，避免误触）。

**数据契约与质量样板在 `data/cards.js` 顶部注释里**，扩写卡片前先读它。
校验：`node tools/card-check.js`（结构 + 引用完整性 + **把每张卡的 `run` 真跑一遍** + 正面有没有泄露答案）。

### 3.12 Android 外壳（`android/` + `tools/build-apk.js`）

**它是新增的分发形态，不是重建。** `index.html` 依然是零依赖零构建、双击就能用的那份文件 ——
APK 只是把同一批文件套了个 WebView 外壳，站点的单一事实来源没变。

```
android/AndroidManifest.xml      零权限清单
android/java/…/MainActivity.java 单 Activity：WebView 配置 + 外链分流 + 返回键
android/res/                     图标（自适应 vector；API 26 以下的 PNG 由脚本生成）
tools/android/icons.js           用代码画图标 → 不往仓库里塞二进制资源
tools/android/zip.js             极简 ZIP 读写，只为把 classes.dex 合进 aapt2 产出的 APK
tools/build-apk.js               八步构建，**不用 Gradle**
tools/apk-check.js               包内容验证
```

**为什么不用 Gradle**：这个项目从第一天起就是"零依赖零构建"。为了打一个包而引入
Gradle + AGP + AndroidX（几百 MB，还要从 Maven 拉）与它的性格不符，也更容易断。
所以直接用 SDK 自带的命令行工具串起来：

```
aapt2 compile   编译 res/                            → res.zip
aapt2 link      链接资源 + manifest + assets/www/    → base.apk（有资源、没代码）
javac + d8      编译 Java                            → classes.dex
zip.js          把 dex 合进去（**不用 `jar uf`**：它会把 resources.arsc 重新压缩，
                而 Android 11+ 要求它未压缩，否则真机上装不上）
zipalign -p 4   对齐
apksigner       签名（自签名，边载安装用）
```

| 设计点 | 做法与原因 |
| --- | --- |
| **零权限** | 不申请任何权限，连 `INTERNET` 都没有。站内全是本地文件；官方文档外链用 `ACTION_VIEW` 交给系统浏览器 —— 一个学习工具不该要你的任何权限 |
| **离线** | 43 个站内文件（3.5 MB）打包进 `assets/www/`，飞行模式可用 |
| **返回键** | 站内是 hash 路由，所以先 `web.canGoBack()` 退历史，到顶了再按一次才退出（"再按一次返回退出"是 Android 上最不容易误触的做法） |
| **软键盘** | 清单里 `windowSoftInputMode="adjustResize"`，配合网页那边的 `visualViewport` |
| **外链** | `file://` 留在 WebView，`http(s)` 交给系统浏览器 |
| **状态栏** | 用站点主色 `#2F6BFF`；**刻意不做 edge-to-edge** —— WebView 对 `env(safe-area-inset-*)` 的支持在 Android 上并不一致，保留系统栏占位更稳 |
| **图标** | 品牌符号 ☁️ + 云里嵌一个终端提示符 `>`。自适应图标用 vector；API 26 以下要 PNG，用代码画（3×3 超采样抗锯齿），保持"仓库里没有二进制资源" |

#### 三个只有 Windows 上才踩得到的坑

1. **aapt2 打不开中文路径**。项目目录是 `E:\云计算-DS`，aapt2 是 C++ 程序、按系统 ANSI
   代码页解析参数，会报 `failed to open directory: 系统找不到指定的文件`（看不出是编码问题）。
   → 构建脚本检测到路径含非 ASCII 时，自动改用 `%TEMP%` 下的纯 ASCII 目录，最后只把 APK 拷回来。
2. **aapt2 把 assets 条目名写成反斜杠**。Windows 上它按本机分隔符写 ZIP 条目，
   产出 `assets/www\index.html` —— **APK 是 ZIP，名字里必须是 `/`**，否则
   `file:///android_asset/www/index.html` 解析不到，装上是白屏。
   → 重打包时统一把 `\` 换成 `/`，并加了断言（这个坑是自检抓出来的，不是肉眼看出来的）。
3. **Node 20 起不能直接 spawn `.bat`**（CVE-2024-27980 之后的限制），
   `d8.bat` / `apksigner.bat` 会报 `spawnSync … EINVAL`。
   → 直接调它们背后的 `d8.jar` / `apksigner.jar`，顺带避开 cmd.exe 的引号与代码页问题。

#### 验证到什么程度

`node tools/apk-check.js`（19 项）做两件事：

1. 把 APK 里的 `assets/www` 解出来，与项目源文件**逐字节比对**（43/43 一致），
   并断言条目名无反斜杠、`resources.arsc` 未压缩、`classes.dex` 在位
2. 把解出来的那份网站在无头 Chrome 里按 **375×667** 真渲染一遍，断言 822 条命令、
   18 个分类、296 张卡片都在，每日一练能翻面、分类页能出卡片、无未捕获异常

`aapt dump badging` 与 `apksigner verify` 也接在构建脚本末尾（包名、label、图标、
launchable-activity、sdk 版本、**权限表为空**、v2+v3 签名有效）。

**没做到的**：没能在模拟器里截到 WebView 渲染的画面。本机雷电模拟器的 adb 桥被
Windows 防火墙拦截，而本会话无法提权（审批已禁用）；模拟器又是 GPU 合成表面，
`PrintWindow` 只能拿到陈旧帧。**能确认的是**：APK 用 `ldconsole installapp` 与
`runapp` 都成功（退出码 0），模拟器内标题栏显示 `CloudCmd`。
其余验证改用上面那条"解包 + 真渲染"的路径 —— 它证明的是"包里那份文件就是能跑的那份"，
这恰恰是打包环节真正会出错的地方。

### 4.3 内容质量红线（写作时必须遵守）

1. **示例必须可运行**：不能出现 `xxx` 这种占位符混在完整命令里（占位符统一写作 `<你的实例ID>` 并在 `desc` 说明）。
2. **不许编造参数**：不确定的参数一律不写，宁可留空；官方文档链接必须能打开。
3. **危险命令必须标警告**：`rm -rf`、`dd`、`mkfs`、`iptables -F`、`kubectl delete`、`DROP TABLE` 等，`notes` 中明确后果。
4. **区分发行版差异**：CentOS/Ubuntu 差异明显的（如 `yum` vs `apt`、`firewalld` vs `ufw`）必须分别给出。
5. **一条命令一个要点**：`summary` 一句话说清"它是干嘛的"，不写"该命令用于……"这类废话开头。
6. **中文标点与英文命令混排**：代码用反引号包裹，全角/半角不混用。

**开发过程中这套测试抓出并修掉的 4 个真实缺陷**（都是"看起来能用、实际是坏的"类型）：

1. **搜索结果页整页空白** —— `CC_SEARCH.query()` 返回的是 `{entry, score}` 包装对象，而 `viewSearch` 直接当成命令对象用，导致每条结果渲染出 `undefined`。因变量名叫 `e`，人工阅读时极难发现。→ 已改为 `results[i].entry` 并加注释。
2. **无意义查询误命中一堆结果** —— 乱序多词兜底逻辑把 `qzxwv` 这类输入按空格切分后词数不足，反而命中了命令名里的短子串，`zzzzz` 都能搜出 `alias`、`cat`。→ 重写打分：分词只保留 ≥2 字符的词，且要求"至少命中 2 个词"，并新增"无意义查询返回 0 条"的回归测试。
3. **`**粗体**` 在页面上显示成裸星号** —— 渲染层 `mdInline()` 只处理反引号行内代码，而六个内容文件共用了 300+ 处 `**粗体**`（内容侧由并行任务产出，无法逐一约束）。→ 在渲染层一处补上粗体支持（先抽出代码片段再处理粗体，避免 `**` 出现在代码里被误转），全站一次性生效；校验脚本同时新增"粗体标记必须成对"检查。
4. **搜索不检索 `notes` 字段** —— 用户搜"反向匹配"找不到 `grep -v`，因为该关键词只在注意事项里。→ 索引新增 `notesN` 并赋权 13；顺带补了"自然语言式提问"的分词回退（"怎么查看磁盘还有多少空间" → `df`/`du`）。

**结论**：内容规模越大，越不能靠"打开看一眼"验收。这两个脚本是 Phase 2 扩量（800+ 条）的前置条件。

**v1.3 做实时练习终端时，同一套测试又抓出 6 个缺陷**，其中两个属于"页面能看、功能全废"的严重级别：

5. **整个终端绑不上事件（最严重）** —— `registerSession()` 里无条件读 `s.lesson.answer`，而"自由练习"终端没有 lesson，抛异常后 `bind()` 中断，结果**页面渲染完全正常、但输入框敲什么都没反应**。修复：判空 + 给 `bind()` 包 try/catch 并在页面上显示错误，避免"静默变成不能用"。
6. **命令的报错被静默丢弃** —— 引擎里命令把错误写进 `ctx.err`、把退出码写进 `ctx.code`，但执行器只读命令的返回值，导致 `ls /nope` **什么都不输出且退出码为 0**。这类 bug 对教学产品是致命的：学员敲错了却得不到任何反馈。修复：执行后回收 `ctx.err` / `ctx.code`。
7. **`cd` 不跨 `&&` 生效** —— `cd /var/log && pwd` 输出 `/root`。原因是每个管道段各自用一份 ctx 快照，改动没写回 shell。修复：执行完把 `cwd` / `env` 写回。
8. **`kubectl get pods` 忽略 kubeconfig 的默认命名空间** —— 硬编码成 `my-app`，反而掩盖了"忘写 `-n`"这个高频错误。修复：默认命名空间从 context 读取（并保持为真实的 `default`）。
9. **合并选项写法失效** —— `ss -tulnp`、`du -sh`、`df -ih`、`grep -rn`、`netstat -tulnp` 都因为只匹配单字符选项而失灵。修复：统一支持 `-abc` 合并写法。
10. **测试工具本身的假阳性** —— 冒烟测试从 dump 出来的 DOM 里抠结果时，匹配到了"被内联进页面的测试脚本源码"里的同名字符串，导致明明跑完了也报"没跑完"。修复：精确匹配带 `style="display: none"` 的结果容器，并从最后一次出现处取值。

**这轮的教训**：给"看起来能跑"的页面写测试，比给纯数据写测试价值高得多 —— 上面第 5、6 条如果只靠人眼打开页面看，几乎不可能发现。

**v1.3.3 做实验台布局时又抓出 1 个同级缺陷：**

11. **终端没有绑定到练习（页面能看、步骤永远不打勾）** —— 布局改成"终端在左、讲义在右"后，两者成了**兄弟节点**，而读取练习 id 的代码还在用 `termEl.closest('.lab-right')`，永远返回 `null`。后果是：终端能敲、命令能跑、输出也正常，**但右侧步骤永远不会打勾、整题永远完不成**。定位方式：在 `run()` 里插探针打印 `s.lesson`，得到 `lesson=NULL`，一行定位。修复：往上找到整个实验台再取练习 id，并加 `document.querySelector('[data-lab-lesson]')` 兜底；同时补了回归测试"终端绑定到当前练习"。

**沉淀下来的方法**：布局重构后，凡是"跨容器读取上下文"的地方都是高危点（父节点关系变了但选择器没变）。这类 bug 不会报错、页面看着完全正常，只有**行为级断言**（"执行第一步后是否打勾"）才能抓到。

**v1.6（手机版 + 引擎扩命令 + 链接体检）修掉的 6 个缺陷：**

22. **引号里的 `>` 被当成重定向** —— 富文本解析器找重定向符号时没有跳过引号内容，于是
    `mysql -e "select id from t where time > 100"` 里的 `>` 被当成"写入文件"，
    **整条 SQL 被悄悄吞掉、还凭空造出一个文件**。加 `mysql` 支持时才暴露。
23. **管道里 `2>&1` 的作用域错了** —— `cmd1 2>&1 | cmd2` 里的 `2>&1` 只应影响 `cmd1` 那一段，
    早期实现让合并标记被后续段覆盖，导致只有最后一段的错误会合并。练习课里
    `nginx -t 2>&1 | tail -2` 是很常见的写法，错了会得到似是而非的输出。
24. **手机端讲义正文只剩 49px（而所有断言都是绿的）** —— 加完手机布局后，
    「讲义面板 ≥200px」这条断言通过了（实测面板 332px），但面板内部
    「头图 92px + 步骤条 85px + 工具栏 + 页脚」把**正文挤到只剩 49px**。
    断言量错了对象。→ 改成断言**正文可视高度**，并把头图瘦身、步骤条改单行横滑、终端让出高度。
25. **`min-height:100vh` 压过 `height:var(--vvh)`** —— 手机端为了适配软键盘，用 `visualViewport`
    把 body 高度写成变量；但基础规则里的 `min-height:100vh` 优先级更高，**高度根本收不回去**，
    键盘一弹出来输入行就被盖住。→ 手机端媒体查询里同时把 `min-height` 清成 0。这条是被
    "模拟键盘弹出"的断言抓到的（把 `--vvh` 压到 367px，断言 body 跟着矮下来）。
26. **`dev.mysql.com` 的 17 条链接被误报成死链** —— Oracle 的 WAF 对任何脚本请求返回 403，
    浏览器里却完全正常。工具最初把它算成"异常"，报出去等于制造噪音。→ 增加**官方镜像代理校验**：
    走 `docs.oracle.com` 的同一页面，镜像 200 说明页面存在，镜像 404 才是真的没了。
27. **华为云 31 条链接被误报成死链** —— 该站对 HEAD 请求返回 **567**（不在任何常见白名单里），
    而 GET 返回 200。工具原本只对 `403/405/501` 降级为 GET。→ 规则改成
    "非 2xx/3xx 一律用 GET 复核"，并新增**失败二次复核**（低并发 + 延迟重跑），
    一次全量跑就从"140 个异常"收敛到"**18 个真死链 + 24 反爬 + 76 限流**"，其中 12 条是复核救回来的。

**v1.6 的一条方法论**：**报错要分类，否则工具会被忽略**。
链接体检第一次跑出 140 个"异常"，里面真死链只有 18 个 —— 这样的输出没人会看第二眼。
把「页面真的没了」（404/410，必须修）和「对方不让你用脚本访问」（403/418/429/567，浏览器里正常）
分开之后，那份 18 条的清单是可以直接派活去修的。
**一个会产生大量假阳性的检查工具，等于没有检查工具。**

**v1.7（每日一练 + 引擎静默错误大扫除）修掉的 10 个缺陷：**

这一轮的触发点很有意思：4 个并行任务在写 **296 张卡片**，它们必须逐条把卡背面的命令
丢进引擎真跑一遍才能确认"说的和跑出来的一致"。结果**引擎里 7 个"静默返回错误结果"的
老 bug 被一次性照出来了** —— 这些 bug 此前一直存在，只是没有人成规模地真跑过。

28. **`find -name` 完全失效（最严重的一个）** —— 收集条件时存的是 `{k:'-name'}`，
    而匹配时比的是 `t.k === 'name'`，两者永远对不上，条件**被静默忽略**：
    `find /data -type f -name "*.log"` 会把 `README.md`、`app.jar` 全列出来。
    命令不报错、退出码 0、输出看着挺正常，**学员据此得出的结论是完全反的**。
29. **`find -perm` 被直接丢弃** —— `find / -perm -4000 -type f` 返回**全部文件**。
    一个"找 SUID 程序"的安全检查变成了"列出所有文件"。已实现完整的
    `-perm 644`（相等）/ `-perm -644`（全含）/ `-perm /111`（任一）三种语义，并补了 `-user`。
    同时给 find 加了**未知选项必须报错**：静默忽略不认识的选项正是上面两个 bug 的共同温床。
30. **`sort -h` 不按人类可读大小排** —— `flags.h` 被解析了，但比较仍是字典序，
    于是 `du -sh /data/* | sort -rh` 的输出顺序是 `8.0K / 5.9G / 245.5M`。
    **顺序全错，却和成功一模一样。** 这是运维最常用的管道之一，而站内速查里就写着它。
31. **`cat` 不跟软链，还把错误当输出** —— `readFileOrErr` 遇到 `link` 节点直接把
    `"cat: xxx: No such file or directory"` 塞进 `content` 返回，于是 `cat /etc/os-release`
    打印出这行"报错"、**退出码还是 0**。根因有两层：引擎不解引用软链，且数据里
    `/etc/os-release` 指向的 `../usr/lib/os-release` 文件名写成了下划线的 `os_release`（死链）。两边都修了。
32. **`lsof -i :8080` 把 `:8080` 丢掉** —— 只认贴写的 `-i:8080`，空格写法下 `port` 为 null，
    命令把**所有**连接都列出来。学员要找 8080，屏幕上却是 sshd。
33. **`sed -n '/起/,/止/p'` 静默输出为空，或输出过多** —— 两个独立缺陷叠在一起：
    ① 地址字符类不含空白与花括号，`/server {/` 匹配失败后整条 part 被**默默跳过**；
    ② 正则范围的分隔符解析漏了一个斜杠（`^\/(.+)\/,(.+)\/$` 应为 `^\/(.+)\/,\/(.+)\/$`），
    "止"永远匹配不上，而匹配失败时 `parseRange` 会**回退成 match-everything**。
    现在地址能用正则了，且**认不出来的 sed 写法会明确报错**而不是静默变空。
34. **`2>/dev/null` 跑不通** —— ① 虚拟 FS 里根本没有 `/dev/null`（`2>/dev/null` 报
    `bash: /dev/null: No such file or directory`）；② 重定向正则不认文件描述符，
    `du -sh /data 2>/dev/null` 里的 `2` 被当成参数传给 `du`。
    现在 `/dev` 下有 `null`/`zero`/`random`/`urandom`/`tty`（**在引擎里建，不依赖 termfs** ——
    设备节点是操作系统的固有部分），`2>` 真正作用于 stderr，`>/dev/null` 是丢弃而不是建文件。
35. **`nc -w 3` 把 `3` 当成主机名** —— 带值的选项必须在"合并字母选项"**之前**判断，
    因为 `-w` 本身也匹配 `/^-[a-zA-Z]+$/`。
36. **`chmod` 完全没有** —— 权限是 Linux 基础的核心内容，而引擎此前**没有任何权限修改类命令**，
    "改了权限再 `ls -l` 验证"这条最经典的学习闭环根本走不通。已实现八进制、符号模式
    （含 `u+x,g-w` 逗号子句、`X` 条件执行位）、`-R` 递归、`-v`，改动落在虚拟 FS 上并真实反映到 `ls -l`。
37. **文档里引用的命令在模拟终端里跑不通** —— 故障速查的 `du -sh /data/* | sort -rh` 撞上
    通配符不展开 + `sort -h` 排序错两个问题。补了**通配符展开**（只在参数含 `/` 时展开，
    避免误伤 `find -name *.log` 这类模式）。

**v1.7 的一条方法论**：**静默的错误结果，比直接的报错危险一个数量级。**
上面 10 个缺陷里有 7 个的共同形态是："命令成功退出、输出看着合理、结论是错的"。
`find -name` 失效会让人以为"日志文件到处都是"；`sort -h` 排错会让人以为"这个目录不大"；
`cat` 把报错当内容会让人以为"文件里就写着这行字"。
**它们不会让任何测试变红，只会让人学到错的东西。**
所以这一轮修完之后，凡是"不认识的输入"一律改成**明确报错**（find 的未知选项、sed 的未知脚本），
宁可打断学员，也不要让他带着错误结论继续往下走。

**v1.8 修掉的两个缺陷 —— 都是"断言写错了，所以永远测不出来"：**

38. **移动端顶栏溢出，把整页撑宽 59px** —— 375px 的屏上文档宽 434，手机上会轻微缩放、
    还能横向拖动。根因是 `.search-wrap` 缺 `min-width:0`：flex 子项默认 `min-width:auto`，
    搜索框按内容宽度撑开后就再也缩不回去，连带把整条顶栏顶破。
39. **而它藏了很久，是因为断言本身写错了** —— 判"有没有横向溢出"用的是
    `document.documentElement.scrollWidth > window.innerWidth`。
    可页面一旦真溢出，浏览器会把**视觉视口一起撑大**（375 的屏上 `innerWidth` 也变成 434），
    于是两边同时变大，**比出来永远是"没溢出"**。正确写法是拿 `scrollWidth` 比
    **`clientWidth`**（布局视口）。已把四处断言全部改正，并补了一条
    "没有被缩小适应"（`innerWidth` 与 `clientWidth` 必须相等）—— 后者能独立地抓住同一类问题。
    **这是本项目第三次遇到同一类教训**（前两次是"量错对象"和"阈值太松"）：
    断言写错的时候，测试会一直绿着，而且绿得很有说服力。

**v2.0 修掉的 16 个缺陷 —— 这一轮的主题是「教材与终端不一致」：**

触发点是一节 shell 练习课。写课的人按任务书要求去教 `while IFS= read -r`，
结果发现**这个构造在引擎里根本跑不出任何输出** —— 于是那节课只能退化成"遍历一个手写的字面量列表"，
并在一堆"本站引擎不支持"的免责说明里绕路。顺着这条线查下去，发现**站内三个条目
（`sh-while-until`、`sh-pipe-cmdsub`、`sh-read`）都白纸黑字写着"管道里的 while 在子 shell 中执行，
所以变量读不到"这个经典陷阱，而引擎的实际行为和它们说的正好相反** ——
教材说输出 `0`，终端输出 `3`。学员照着课本在终端里验证，会得到"课本写错了"的结论。

40. **`$(( ))` 算术展开完全不可用（最严重）** —— `maskBlocks` 在屏蔽"不该当元字符的括号"时，
    把 `$((2+3))` 内层那个 `(` 也一并换成了 NUL（因为它前面不是 `$`）。下游的 `extractSubs`
    再也认不出这是算术展开，把它当成"命令替换，命令是 `(2+3)`"去执行一条不存在的命令、
    拿到空值。后果：`echo $((2+3))` **静默输出空行**、`N=$((N+1))` 把计数器**清空**、
    循环计数器永远不动。全程没有任何报错，退出码 0。
    → `maskBlocks` 增加 `$((` 分支，整块原样保留；`extractSubs` 同步不再把它当命令替换。
41. **`[ ]` 数字比较恒真/恒假 + 双目操作数取反（两个独立缺陷叠在一起）** ——
    ① `testTokenize` 的词扫描只把 ` \t"'()!<>=,;` 当边界、**不把 `-` 当边界**，
    于是 `[ 1 -lt 2 ]` 到达求值器时 argv 已经是 `['1 -lt 2']` 一个词，
    `toks[p+1]`/`toks[p+2]` 取不到运算符与右操作数，整式被判"表达式语法错误"；
    ② 更隐蔽的是 `var a = toks[p + 1], op = toks[p + 2]` —— **两个变量取反了**，
    `a` 拿到的是运算符本身。于是 `[ "$A" = web ]` 恒为假（拿 `=` 当模式去匹配 `web`）、
    `[ 1 -lt 2 ]` 恒为真（运算符位置拿到 `2`，落进"单个词非空即真"分支）。
    **两者都不报错** —— 修复后 `while [ $i -lt 3 ]` 这类循环才第一次真正可用。
42. **`A && B || C` 里 A 失败会 `break` 整行** —— 真 shell 的语义是 `(A && B) || C`：
    A 失败时 `A && B` 整体为假，C **必须执行**。原先第一个失败就跳出整个语句列表，
    于是 `false && echo yes || echo no` 什么都不打印，`ls /nope 2>/dev/null && echo 成功 || echo 失败`
    也没有任何输出。"少打印一行"没有任何报错，退出码也像是正常的。
    → 改成 `continue`（只跳过那一个操作数，且**保持 code 不变**，后面的 `||` 才知道前面失败了）。
43. **`while read … done < file` 循环体一次都不执行（而屏幕上什么都不说）** ——
    执行器在每个命令前把 stdin 交给 shell 时写的是
    `self._readStdin = cmdStdin ? {…} : null` —— **无条件**。没有管道也没有 `<` 的命令
    会把循环流抹成 null，`read` 立刻返回 1、条件永远为假。
    改用输入重定向后**变量还能正确带出循环**，这也正是教材里"两种写法一个有坑一个没坑"的对照。
44. **`for i in $(seq 1 3)` 迭代出 `$(seq`、`1`、`3)` 三个字面量** ——
    `for` 的词表在解析阶段就被按空格切开了，命令替换结果永远轮不到展开。
    → 词表保留原文，执行时先跑命令替换，再按 bash 的 IFS（空格、制表符**和换行**）切词。
45. **`case` 把待匹配的词当命令执行** —— `ctrlRunCase` 里写的是
    `shell._execCommand(ctrl.word, …)` 再取它的 stdout 当词用。于是 `case abc in abc) …`
    先冒一句 `bash: abc: command not found`，`case $V in x) …` 更糟（`$V` 展开成 `x` 之后又被当命令跑）。
    **两边的分支照样匹配**，所以结果看着"半对"，特别容易骗过人。
    → 改成对一个**词**做变量替换与命令替换（不执行它）。
46. **`ctrlParseCase` 吞掉 `esac` 之后的所有语句** —— 它用 `stmts.slice(fromIdx)` 取到行尾，
    于是 `for H in a b; do case $H in …) … ;; esac; echo "$H 属于 $T"; done`
    里循环体最后那条 `echo` 被当成了 case 最后一个分支的动作，**循环体什么都不打印**。
    → 扫到 `esac` 所在语句为止，`next` 也相应修正。
47. **循环体里不能嵌 `if`** —— 循环体/分支体是按 `{cmd, op}` 列表逐条执行的，
    而 `if` 天然跨越多条（`if … then … fi`），单条丢给 `_execCommand` 就报
    `bash: if: command not found` 外加一串"then 必须与 if 配套"。
    "循环里做判断"是最常用的写法之一，此前完全不可用。
    → 抽出 `ctrlParseList(stmts, fromIdx)`，循环体按**语句数组**递归解析控制流。
48. **管道接控制流不可用** —— `… | while read l; do …; done` 在 `splitByAnd` 阶段
    就被循环体里的 `;` 切成了三段（`… | while read l`、`do …`、`done`），
    `while` 永远配不上 `do`。→ 新增 `splitPipedControl`：把"管道头"与"控制流"拆成两条语句，
    控制流那条带 `pipeFromPrev`，由 `_execScript` 把管道头的 stdout 接成它的输入流。
49. **管道里的循环不在子 shell 里（教材一致性问题）** —— 真 shell 里管道的每一段都在子进程里，
    所以 `n=0; cat f | while read l; do n=$((n+1)); done; echo $n` 输出 **0**。
    站内三个条目都写了这一点，引擎却输出 3。→ 多段管道与"管道接控制流"都改用
    **变量表副本**执行，退出时还原；单条命令（`X=1`、`cd /tmp`）不受影响。
50. **`ls | wc -l` 恒等于 1** —— 真 `ls` 会看 stdout 是不是终端：是终端按列排版（一行塞好几个名字），
    被重定向或进管道则**一行一个**。引擎一律按列（把名字用两个空格拼成**一行**），
    于是 `ls /data/backup | wc -l` 得到 **1**（其实是 16 个条目）、`ls | head -3` 也只出一行。
    一个"看着很合理的数字"其实是错的 —— 这种错误比报错危险得多。
    → 由 `_execOne` 按"是否管道非末段 / 是否有输出重定向"算出 `ctx.tty`，`ls` 据此决定排版；
    顺带支持了 `ls -1`。
51. **`> 文件 2>&1` 只写 stdout，stderr 还在屏幕上** —— `2>&1` 的合并只在
    `_execOne` 的**最后**做一次（把 `err` 并进 `out`），而文件早就写完了。
    → 写文件时就把 stderr 一起写进去，终端上两路都不再出现。
52. **`> out 2> err` 会把 `>` 当成参数传给命令** —— `extractRedirect` 只处理**末尾那一个**重定向：
    `2> err` 被认走之后，`> out` 已经不是末尾，于是原样留在命令行里变成参数。实测
    `ls -l /etc/hostname > /tmp/a.log 2>/tmp/b.log` 会把 stdout 打到屏幕上、还报
    `ls: cannot access '>'` —— **命令的真实行为被改掉了，却给出一句像是"文件不存在"的正常报错**。
    → 改成循环剥离，把所有输出重定向按先后顺序全部应用。
53. **`X=$(cmd | awk …)` 报"命令替换括号不配对"** —— 切管道用的是 `maskBlocks` 的结果，
    而它不屏蔽 `$( )` 的**内部**，于是替换式里的 `|` 被当成外层管道的分隔符，
    整行切成三段、第一段括号不配对。变量静默为空，只留一句看不懂的括号报错。
    → 新增 `maskSubInteriors()`，**只给切分用**（并进 `maskBlocks` 会让 `extractSubs` 拿不到原文）。
54. **`${VAR:?}` 打印 `undefined`** —— 原实现是 `if (op === '?') return cur;`，
    变量未定义时把 JS 的 `undefined` 直接返回出去，屏幕上打出一句莫名其妙的 "undefined"：
    既不报错、也不为空。→ 改为按真 shell 报错并让这条命令以非 0 退出（`bash: NAME: 提示`）。
55. **`${VAR:=}` 写不回变量表；`N=$(… | wc -l)` 被前导空格切成空** ——
    ① 展开时用的是一份 `vars` **副本**，`${VAR:=}` 写进去的是副本，后面再引用就没了；
    ② `N=$(cmd | wc -l)` 的值是 `"      5"`（`wc` 的输出带前导空格），而引擎是
    "先把替换结果写回文本、再切词"，于是被切成 `N=` 与 `5` 两个词 —— 变量静默为空，
    还多报一句 `bash: 5: command not found`。→ 传出 `setVar` 回写真正的 env；
    纯赋值形态（`名字=单个命令替换`）单独处理，不做字段切分（真 shell 的赋值也不切）。

**配套的内容与测试改动**：shell 课程 **5 → 7 节**（第 2 课改用 `while IFS= read -r`、
第 4 课补 `${VAR:?}` 真校验、第 5 课补 `2>&1` 顺序的正反实验、新增第 6 课「子 shell 陷阱」
与第 7 课「case 分派」）；第 1 课那个会真删 `termfs` 共享文件的步骤改成在 `/tmp` 副本上演练；
`tools/about-leak-check.js` 改用与 `hint-check` 共用的 `tools/_stepscan.js` 扫描
（原先只认单行步骤对象，多行写法会被**整份跳过**而工具照样报"全部通过" —— 覆盖率从 309 涨到 310 时才暴露）；
`shell-check` 的断言 **438 → 511**，新增的全部断言**断言输出内容而非退出码**。

**v2.0 的一条方法论**：**教材与终端必须互相印证，否则学员会先怀疑教材、再怀疑整个站。**
这 16 条里有 9 条是"静默给出错结果"（不报错、退出码还是 0），而它们能活这么久，
恰恰是因为**五道闸门一直是全绿的** —— 闸门测的是"命令能不能跑、字段全不全"，
而"跑出来的值是错的"没有断言去管。所以这一轮每修一条都补了内容级断言。

**v2.1 修掉的 2 个缺陷 —— 都是「标注的假阳性」：**

这一轮在补连贯性最后一环（故障剧本）与"未实现命令诚实提示"时，
**两次都把标注做得太宽**，两次都是当场发现并修掉的。它们不会让任何页面报错，
只会让学员**学会无视那个标注** —— 而这比没有标注更糟。

56. **「仅真机」按"首词不在实现表里"一刀切，把跑得通的循环也标了** ——
    故障剧本里有 `for h in <域名1> <域名2>; do … openssl s_client …; done` 这类复合行，
    首词是 `for`，而 `for` 当然不在引擎的命令表里，于是整行被标成"跑不了"。
    可它跑得通（`openssl`、`date`、`cut` 都是实现了的）。
    → 判据改成：首词是 shell 关键字（`for/if/while/until/case/do/then/else/fi/done/esac`）
    就**不按首词判**，改为检查行内有没有出现在 `notImplemented` 表里的真命令。
    实测从"标 7 处"收敛到"标 5 处"，被去掉的正是那两行假阳性。
57. **"跑不了"挂在了根本不是命令的条目上** —— 手册里有一批条目名是
    SQL 关键字 / K8s 对象 / 产品名 / 中文概念：`SHOW`、`EXPLAIN`、`Pod`、`Service`、
    `LVM`、`Jenkins`、`GitLab`、`AK/SK`、`华为云`…… 它们本来就不是 shell 命令。
    按"首词不在实现表里就提示"，给这些条目也挂上"这条命令在模拟终端里跑不了"，
    纯属噪音。
    → 加前置判断：首词得**像一条命令**（`/^[a-z][a-z0-9._+-]*$/`、长度 ≥ 2）才提示。
    并补了一条**防假阳性断言**：`SHOW`/`Pod`/`LVM`/`华为云` 这些条目必须**不出现**提示。
    按修正后的判据，会显示提示的有 169 / 825 条（20%），涉及 152 个命令 ——
    这个量级是"有用"，而不是"到处都是"。

**v2.1 的一条方法论**：**标注的假阳性会训练用户无视标注。**
上一轮（v2.0）的教训是"静默的错误结果比报错危险一个数量级"；
这一轮补上后半句 —— **一个到处乱标的提示，比没有提示更糟**，
因为学员会先学会忽略它，然后连真该看的那几条也一起忽略。
两次假阳性都是靠"把标注数量打印出来、逐条人工核对"发现的：
数字从 7 掉到 5、提示从 309 条收敛到 169 条，**每一次收敛都是把假阳性挤出去**。

**v2.2 修掉的 8 个缺陷 —— 全部是从 `example-check` 的长尾里挖出来的：**

长尾（45 条报错）此前一直被当成"内容写得不严谨"。这一轮逐条看下去，
发现里面**混着真 bug**：有些示例的参数完全正确、却因为引擎不认某个带值选项而跑不通；
还有一条干脆是引擎抛异常。这印证了一件事 ——
**把长尾笼统归成"内容问题"会掩盖引擎缺陷；必须逐条看，而不是数个数。**

58. **`ansible-config init` 直接抛异常**（`tpl.split is not a function`）——
    `configTemplate()` 返回的是**行数组**，调用方却写 `tpl.split('\n')`。
    学员看到的是"引擎抛异常"而不是配置模板，而
    `ansible-config init --disabled -t all > ansible.cfg` 正是站内的示例。
59. **`timeout -s KILL` 把信号名当命令执行** —— `-s` / `-k` 是带值选项，
    早先只把 `-s` 本身跳过去，`KILL` 于是落进"要执行的命令"里，
    报 `bash: KILL: command not found`。而 `timeout -s KILL 10 …` 恰好是强杀挂死进程最常用的写法。
60. **`sort -T / -S` 的值被当成待排序文件** ——
    `sort -u -T /data/tmp -S 2G 文件` 报 `sort: /data/tmp: Is a directory`，参数完全正确。
61. **`jq --arg 名字 值` 是"两个参数"的选项** —— 早先只跳过长度 ≤ 3 的短选项，
    于是 `--arg` 被当成过滤器、`ns` 被当成文件，报 `Could not open ns`。
    `--arg` 是把 shell 变量安全传进 jq 过滤器的标准做法。
62. **`nginx -p <前缀>` 报 invalid option** —— `-p` / `-g` 也是带值选项。
    `nginx -t -c /etc/nginx/nginx.conf -p /etc/nginx` 是最常见的"用指定前缀试配置"写法。
63. **`(命令)` 子 shell 完全不可用** —— maskBlocks 把括号块屏蔽成 `\x00`，
    于是命令名变成一串 NUL，报 `bash: (echo: command not found`。
    而 `(echo > /dev/tcp/10.0.1.23/80) 2>/dev/null && echo 可达 || echo 不可达`
    正是站内 `sh-devnull-devtcp` 条目教给学员的端口探测写法 ——
    **教材在用、引擎不认**。现已支持，并按真 shell 语义给它独立的变量副本。
64. **`sh -c "…"` 不可用** —— `sh` 由 `shDispatcher` 实现，它把第一个参数当成"脚本文件名"，
    于是 `-c` 被当成文件名，报 `sh: 0: cannot open -c`。
    `xargs -P 5 -I{} sh -c "sleep 1; echo 处理 {}"` 是并发批量的标准写法。
65. **`curl` 访问 IP 字面量报"域名解析失败"** ——
    `curl http://10.0.1.31:8080/health` 报 `curl: (6) Could not resolve host: 10.0.1.31`。
    **IP 字面量根本没有 DNS 解析这一步**，这条报错会把学员引去查解析，
    而真机上对应的结果是连接类错误（7 拒绝 / 28 超时）。
    改为按"连接被拒绝"报，指向的正确下一步是"服务没起 / 端口不通"；
    只有**域名**形式的未知主机才报解析失败。

**v2.2 还修掉一个测试自身的缺陷**（比上面 8 条更值得记）：

66. **一条断言删了共享文件却不还原** —— `shell-check` 里"配置不存在时 nginx -t 报 open() failed"
    这条断言直接 `rm /etc/nginx/nginx.conf`，而**所有断言共用同一份虚拟文件系统与同一个 shell**，
    删完从不恢复。后果是几百行之后任何用到这个文件的断言都会以"文件不存在"失败，
    **而失败信息指向被测代码、完全不提是前面那一条把它删了**。
    这一轮加 `nginx -p` 断言时正好撞上，才发现它一直在污染后面的断言。
    现在改成"备份 → 断言 → 还原"，并补了一条**元断言**：
    "上一条删掉的配置必须被还原"。
    教训与 v1.5 第 10 条（测试工具的假阳性）、v2.1（标注的假阳性）同源 ——
    **测试环境也是共享状态，写断言时必须像写生产代码一样考虑副作用。**

**v2.3 修掉的 6 个缺陷 —— 三个是确认清单里的，三个是加断言时"顺手"照出来的：**

前三个来自用户确认的施工单（"站内自己在教的写法跑不通"），后三个是**为这一批新命令写断言时
被断言逼出来的** —— 这再次印证：**写断言的过程本身就是一次独立复核**，
只实现不写断言，这些 bug 会以"命令能跑、结果不对"的形态留下来。

67. **`grep --include=` 参数错位** —— `--include` / `--exclude` / `--exclude-dir` 是
    **带值的长选项**，而 `grep` 的选项解析只认短选项与几个固定长选项，于是
    `--include=*.log` 一路落进位置参数、被当成**模式**；真正的模式 `ERROR` 反而成了
    "要搜索的文件"，报 `grep: ERROR: No such file or directory`。
    参数完全正确却跑不通，而 `--include` 是"只在某类文件里搜"的标准写法，
    站内 `lt-grep` 条目就在教它。已实现三个选项（含空格写法）并在递归遍历时按
    文件名/目录名过滤。
68. **子 shell 带输出重定向失效（两个独立缺陷叠在一起）** ——
    ① `extractRedirect` 只认"行尾的重定向"，`(echo hi > /tmp/f)` 里的 `)`
    被当成文件名的最后一个字符一起吃掉，括号不配对 → `bash: (echo: command not found`；
    ② 而 `(echo hi) > /tmp/f` 先被摘掉重定向，子 shell 分支**直接 return**，
    把"把结果写进文件"整个跳过 —— 文件永远不生成。
    合并后两类写法都跑不通。改为：先按括号配对拆出"子 shell 内容 + 尾部重定向"，
    内容交给引擎再跑（真 shell 里子 shell 有自己的变量副本），尾部重定向用
    控制流那套 `ctrlApplyOutRedirs` 应用到结果上。
69. **`/dev/tcp/<主机>/<端口>` 端口探测永远返回"不可达"** ——
    `(echo > /dev/tcp/10.0.1.23/80) 2>/dev/null && echo "80 端口可达" || echo "80 端口不可达"`
    是站内 `sh-devnull-devtcp` 条目亲自教的、不依赖 `nc`/`telnet` 的探测写法，
    而引擎把它当成普通文件路径，报 `No such file or directory` ——
    **教材在用，终端却永远说不可达**。现按模拟监听表实现连接测试语义：
    绑 `0.0.0.0` 的端口任何主机可连、绑 `127.0.0.1` 的只有本机可连
    （后者正是"服务只听本地"这个高频故障的教学点）。
70. **`ln -sfn` 会把软链变成 0 字节普通文件** —— `ln` 只用 `argv.indexOf('-s')` 认 `-s`，
    于是 `-sfn`（原子切换版本软链的标准写法）识别不到 -s，整条命令退化成"建硬链接"，
    把一个软链**变成一个空文件**。而站内 `lb-ln` 正在教 `ln -sfn`
    （"原子切换版本链接，`-n` 防止在旧版本目录里再建一个链接"）。
    已改为按合并写法解析，并补齐 `-f` 覆盖、`-n`、`-t`、`-T`、`-v` 与
    "目标已存在且是目录时链接建在目录里面"的真机语义。
71. **`sort -o 文件` 被吃掉却不写文件** —— `-o` 与 `-T`/`-S` 一起被当成"带值选项"跳过，
    但**没有真的写文件**：命令成功退出、该出现的文件却不存在，是典型的
    "成功但没做事"。站内示例 `sort -u "$f" -o "$f.u"` 依赖它产出 `.u`，
    后面的 `sort -m ./part-*.u` 于是整条链断掉。已实现（写文件且标准输出为空，与真 sort 一致）。
72. **`findNode` 不跟"路径中间"的软链** —— termfs 里 `/opt/myapp` 是指向 `/data/app` 的
    软链，于是 `cat /opt/myapp/start.sh`、`nohup /opt/myapp/start.sh` 全部报"文件不存在"，
    而文件好好地躺在 `/data/app` 下。已改为只跟**中间**软链（最后一段不跟 ——
    否则 `ls -l /etc/os-release` 显示不出它是个软链、`readlink` 也没东西可读，
    这个边界第一次改过头了，被断言当场抓住）。

**外加一个工具自身的缺陷**：

73. **`insert-record.js` 的缩进处理会把新记录"藏"起来** —— 它给片段无脑补 4 个空格，
    于是作者写成 4 空格起的片段变成 8/10 空格。页面照常工作，但
    `tools/apk-check.js` 的 `countSourceCommands()` 是按 `^\s{6}id: '` 数条数的，
    **新增的 5 条记录被漏数**，报出"APK 里的数据与源码不一致（825 ≠ 830）"——
    看起来像 APK 坏了，实际是计数器的缩进假设被打破。
    已改为按片段的最小缩进归一化；并把那 5 个记录块的缩进改写回标准。

**v2.3 的一条方法论**：**"实现完就跑一遍断言"不是流程，是复核。**
上面 70~72 三个缺陷都不影响"命令能否执行"，只影响"结果对不对" ——
它们全部是在**为新命令补断言**的过程中被逼出来的
（`ln -sfn` 之后 `ls -l` 该以 `l` 开头、`sort -o` 之后文件该存在、
`cat /opt/myapp/...` 该读到内容）。如果只实现、不写断言，
这三个 bug 会以"命令能跑"的形态长期留下来。

**v2.5 修掉的 4 个缺陷 —— 两个"口径/解析"问题、一个判据假阳性、一个崩溃：**

74. **`notImplementedReason()` 只查了一张表** —— 未实现的原因登记在**两张**表里：
    `NOT_IMPL`（命令存在但本站不做：`ssh`、`iptables`、`less`…）与
    `SHELL_EXTRA_UNSUPPORTED`（shell 内建/语法：`trap`、`set`、`source`…）。
    查询函数只查了前者，于是 `trap`/`bash`/`nohup` 在**终端里**有具体解释、
    在**命令详情页**却退化成"教学环境没有实现它" —— 同一件事两种说法。
    这类"同一个事实存在两处、只更新了一处"的缺陷没有任何报错，只能靠断言发现。
75. **第三类「仅真机」假阳性：配置指令 / SQL 语句** —— 手册里有一批记录描述的是
    "某个配置文件里该怎么写"：`location [ = | ~ | ~* | ^~ ] <模式> { ... }`、
    `proxy_pass <上游>;`、`locals { <名字> = <表达式> }`、`SHOW PROCESSLIST;`。
    首词恰好也是小写 ASCII，于是被挂上"这条命令跑不了"。判据（**先剥引号、再剥 `#` 注释**）：
    含块语法 `{` 或以 `;` 结尾。剥注释这半步是必需的：
    `client_max_body_size <大小>;   # 可写在 http 块` 不剥注释就会漏网。
    配了**双向断言**：配置条目必须**不给**提示，同时 `ssh`/`iptables`/`useradd` 这些
    真命令必须**仍然给**提示 —— 否则判据可能宽到把命令也一起吞掉。
76. **`yq` 的 YAML 解析把数组多套了一层** —— `key:` 后跟 `- item` 时数组被建在子对象里：
    `.spec.template.spec.containers` 取出来是 `{"containers":[…]}` 而不是 `[…]`，
    于是 `containers[0].image` **永远取不到值**（`[]` 展开也只会拿到那个多余的对象）。
    这是"极简解析器"最容易犯的错：解析时还不知道这个 key 该是对象还是数组。
    改成"**先看下一条有效行的形状再决定建对象还是数组**"。
77. **`join -a 1`（左外连接）直接把终端打断** —— 遇到没有匹配的左表行时，
    `pick(null, i)` 去 null 上取下表，抛 `Cannot read properties of null`。
    这条缺陷只有**断言真的走"有未匹配行"这条路径**才能抓到：
    写断言时如果只用一个"两边全能匹配"的夹具，它会一直绿着。

**v2.5 的一条方法论**：**"未实现"三个字是最没用的反馈。**
这一轮把 60 个会给提示的命令**全部**补上了具体原因（平均 115 字），
并且要求原因里必须包含三件事之一：**为什么不做**（真实网络/内核/交互式）、
**去哪儿学**（指向站内条目）、**用什么替代**（`rg` → 用 `grep -r`；
`nohup` → 用 systemd；`rmdir` → 用 `rm -d` 但要先 `ls`）。
判断标准很朴素：**学员看完这句话，知不知道下一步该干什么。**

另一半是**第三类假阳性的教训延续**：给"跑不了"加标注这件事，
已经连续三轮各发现一类误标（v2.1 的 `for` 复合行、v2.2 的非命令条目、v2.5 的配置指令）。
规律完全一样 —— **判据只要用"看起来像"的启发式，就一定会误伤**；
唯一稳的做法是**用数据自己的结构说话**（`syntax` 首词一致、块语法、语句终止符），
并且**每条判据都配一个反向断言**。

**v2.6 修掉的 9 个引擎缺陷 —— 全部是"给示例写断言"这一步逼出来的：**

78. **`git init -b <分支> <目录>` 把分支名当成了目录** —— `-b` 是带值选项，但它落进了
    "按字符拆开"的通用分支，于是 `git init -b main myapp` 变成
    `flags.b=true` + 位置参数 `['main','myapp']`，`init` 取 `pos[0]` 当目录，
    **在 `/root/main` 建了仓库**，学员要的 `myapp` 根本不存在，紧接着的 `cd myapp` 报错。
    真机上这是极常见的一条命令。
79. **`git checkout -b` 在"还没有任何提交"的仓库里报错** —— `git init x && cd x &&
    git checkout -b foo` 在真机上会说 `Switched to a new branch 'foo'`，
    而引擎硬要求 `gitHead` 有值，报 `fatal: not a valid object name: main`
    —— 而 `main` 根本还没诞生，这句报错没有任何指导意义。
80. **用路径调用命令报 `command not found`** —— 真 shell 里 `$JAVA_HOME/bin/java -version`、
    `/usr/bin/python3 -V` 都合法。引擎只按整串查表，于是站内 `sh-var-export` 的示例报
    `bash: /usr/lib/jvm/java-17-openjdk/bin/java: command not found`，
    **学员会以为 JDK 没装**。改为回退到 basename 查表。
81. **`ssh-keygen -l -f` 不读虚拟文件系统** —— 它只查一张写死的表，于是
    `/root/.ssh/id_ed25519.pub` 明明 `cat` 得出来，`ssh-keygen -l -f` 却报
    `No such file or directory`，而站内 `ln-ssh-keygen` 教的正是"核对公钥指纹"。
    改为从文件内容解析类型/注释，指纹用 xorshift 确定性算出
    （同一文件永远同一个值，才能做核对练习）。
82. **`docker volume inspect` 忽略卷名与 `-f` 模板** —— 无论传什么名字都返回第一个卷，
    且 `-f "{{.Mountpoint}}"` 被整个忽略，把整段 JSON 灌进了命令替换，
    于是 `du -sh $(docker volume inspect -f …)` 收到 `[`、`{`、`CreatedAt:` 这些"文件名"。
    **参数被静默忽略**比报错更难发现。
83. **`systemctl show -p MainPID --value` 未实现** —— 返回空，于是
    `cat /proc/$(systemctl show -p MainPID --value myapp)/limits` 展开成 `cat /proc//limits`。
84. **`helm show` 只做了 values/chart** —— `helm show readme` / `all` 报 unknown command；
    **`helm diff upgrade` 报 `helm diff diff`**（`stripHead` 只剥掉 `helm`，子命令组名
    `diff` 没剥，导致后面所有下标错位）。
85. **通配符只在最后一段展开** —— `/var/log/batch-*/10.0.1.21.out` 与
    `/var/lib/docker/containers/*/*-json.log` 永远报"文件不存在"。改为**逐段展开**
    （真 shell 行为）；顺带归一化 `.` 与 `..` 段，否则 `./part-*` 这种写法匹配不上
    （`findNode` 不认 `.` 这个段）。
86. **`id <用户>` 无论传什么都返回 root 的身份** —— 一条完全写死的输出。
    后果是站内 `lu-who-can-sudo` 那节课要学员 `id deploy` 看附加组，拿到的却是 root；
    权限排查里"这个账号属于哪些组"是最关键的一步，**返回错的答案比报错危险得多**
    （学员会据此得出"它没有提权权限"的错误结论）。

**外加一个"检查器自己脏了"的缺陷（这一类最值得记）：**

87. **`example-check` 用共享 shell 跑全部示例，把正确的示例判成了缺陷** ——
    它依次跑 3254 条示例，而像 `mv /var/log/nginx/access.log …$(date +%F) && nginx -s reopen`
    这样的示例**本来就是"把日志改走"**，于是排在其后的示例读不到文件、报 `No such file`。
    受害的有 5+ 条，**而真正的缺陷被淹没在这些噪音里**。
    粒度是实测选出来的（同一次运行比三种）：
    **共享 shell → 报错 38 条；每条记录一个 → 报错 32 条；每条示例一个 → 报错 48 条**。
    取"每条命令条目一个"：记录内的示例**本来就是接力的**（ex1 `cp` 出文件、ex2 再 `diff` 它），
    全拆开等于把正常叙事判成缺陷。这条与 §6.5 第 66 条（断言污染）是同一类问题：
    **测试环境也是共享状态，写断言时必须想着副作用。**

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 命令数量庞大，内容质量下滑 | 站内出现错误命令，失去信任 | 分任务产出 + 校验脚本 + 抽查 10%；不确定就不写 |
| 云厂商 CLI 版本迭代快 | 部分命令过时 | 每个命令附官方文档链接；页面标注"核对版本" |
| **华为云命令写错**（操作名/region/参数） | 用户照抄执行失败，信任崩塌 | 严守 §3.7 红线；只写能查证的；标注"以控制台/官方文档为准" |
| **模拟终端被误当成真机** | 用户在真机上照抄仿真结果，操作失败 | 页面顶部醒目标注"模拟环境/不能替代真机验证"；无法模拟的命令明确说原因而非假装成功；README 与文档同步说明 |
| 单文件数据过大导致首屏慢 | 体验下降 | 按分类分文件按需 `<script>` 注入；Phase 1 预算 < 600KB |
| 内容版权 | 合规风险 | 只写自己的说明与示例，官方文档仅放链接不摘抄全文 |
| 范围膨胀（想加视频/后端） | 永远做不完 | 严格执行 §1.5 非目标 + §4.4 分期 |
