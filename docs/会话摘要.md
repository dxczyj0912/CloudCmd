## 1. 项目是什么

**CloudCmd · 云计算命令手册** —— 零依赖、离线可用的云计算学习站。工作区 `E:\云计算-DS`，双击 `index.html` 即可用（不需要服务器、不需要构建）。

**硬约束（贯穿所有决策）**：零 npm 依赖、零构建。因为第一使用场景是双击本地 HTML 打开，`file://` 下 ES Module 的 `import` 和 `fetch(json)` 会被 CORS 拦死，所以数据用传统 `<script>` 注入全局变量、逻辑用 IIFE 包裹。这是刻意取舍，不是技术债。

## 5. 学习平台的关键机制

- **终端跑真 shell**：`shell.js` 有 339 个命令的真实现（`ls -l` 算权限位、`du` 遍历树、`kubectl describe` 从对象拼装、`mysql` 真解析 SQL、`nginx -t` 真解析配置、`hcloud`/`obsutil` 返回结构化 JSON）。输出是算出来的，不是预置字符串。
- **命令模块化（add-only）**：`window.CC_SHELL.extend({name: fn})` 注册新命令，`fsAdd({path:{…}})` 补虚拟文件系统夹具。**⚠️ `extend` 永不覆盖** —— 注册一个 `CMDS` 里已存在的名字是**静默无操作**（踩过两次：`gzip`、重复的 `java`）。要改已有命令只能改 `shell.js` 本体。
- **实例级环境覆盖**：`CC_SHELL.create({hostname, ip, gateway, nic, dns})` —— 每个实例克隆一份环境，互不污染。主站是 `web-prod-01`/`eth0`/`10.0.1.23`；练习平台是 `cloudcmd-lab01`/`ens160`/`192.168.17.10`。
- **步骤判定**：执行某步的命令（归一化后前缀匹配）即打勾；全部完成才打卡、展开讲解、终端打印 🏆。进度存 `cloudcmd.practice.v1`（与主站的 `cloudcmd.v1` 分开）。
- **临时 Shell 窗口**（主站）：`Ctrl`+`\`` 或顶栏按钮，可拖拽左边缘（键盘 `←→` 步进 32px、`Home/End` 到极值）、可折叠成窄栏，状态存 localStorage。**`bindPanel()` 独立于 `bindInner()`，面板会话不进 `sessions` 数组**，所以随手敲命令不会污染练习步骤判定。
- **场景名自动回落**：`academy-lab.js` 的 `sceneOf()` 只保留少量人工命名覆盖，其余回落到 `_registry.js` 的分类名 —— 新增分类不用改这里。
- **手机端三件事**（都在 `academy-lab.js` 的 `bindMobile()` 与 `lab.css` 的 `≤760px` 段）：
  ① **快捷键条**给手机上难敲的 `|` `~` `$` `*` 和没有的方向键，点符号会**插到光标处**（不是追加），`↑`/`↓` 与物理键盘共用同一份历史逻辑；
  ② **软键盘**用 `visualViewport` 写 `--vvh`，body 高度跟着收缩 —— **必须同时清掉基础规则里的 `min-height:100vh`**，否则高度收不回去；
  ③ **讲义与终端同时在场**：讲义占满剩余空间、终端贴底 34dvh，可一键切全屏终端。判据是**正文可视高度 ≥150px**，不是面板高度。
- **数据契约**：命令对象的必填字段 = `id`/`name`/`level`/`syntax`/`summary`/`examples`，id 前缀按分类固定（`lb-`/`lt-`/`lu-`/`ln-`/`ls9-`/`sh-`/`dk-`/`k8s-`/`hl-`/`mw-`/`db-`/`mo-`/`hw-`/`iac-`/`ci-`/`vm-`/`sec-`/`pf-`）。
- **⚠️ 练习课的硬前提**：每一步都是真跑的，所以**只有引擎实现过的命令才能出练习课**。
  仍没实现的：`terraform`/`ansible`/`virsh`/`qemu-img`/`openssl`/`ab`/`wrk`/`fio`、
  `wget`/`rsync`/`scp`/`iptables`/`useradd`/`certbot` 等约 59 个，以及 shell 内建 `set`/`trap`/`for`/`if`。
  **另一条更隐蔽的坑**：`example-check` 把"未实现命令"的示例算作 **SKIPPED**，
  所以**实现一条命令 = 把它的示例从"跳过"变成"真测"** —— 命令与夹具必须同时到位，否则失败数不降反升。
  命令覆盖表见 `docs/内容规范.md` §5.3。
- **⚠️ APK 的真实构建目录在 `%TEMP%`，不在项目里。** 项目目录名是中文（`E:\云计算-DS`），
  aapt2 在 Windows 上按 ANSI 代码页解析路径参数，中文路径会让它直接报
  "failed to open directory: 系统找不到指定的文件"（且看不出是编码问题），
  所以 `build-apk.js` 改在 `%TEMP%\cloudcmd-apk-build` 构建，最后只把 APK 拷回项目根。
  **项目根那个 `build-apk\` 是早期遗留的陈旧快照**（里面的文件时间戳可能停在很久以前），
  **别拿它判断"某个文件在不在包里"** —— 判断包内内容要直接读 APK
  （`tools/apk-check.js` 就是这么做的）。（踩过：删掉一个文件后用陈旧的 `build-apk\` 去确认，
  差点得出反的结论。**验证要用真数据源，不要用缓存/派生物。**）

### ⚠️ 引擎的"子集实现"清单（写课前必查，否则会写出"教了但跑不出结果"的课）

v3.5 的**全部 8 个静默缺陷**都是这样来的：命令能跑、但**某个参数被悄悄忽略**，
输出看起来完全正常。**这类问题比 `command not found` 危险得多** —— 后者学员立刻知道敲错了。

| 命令 | 被静默忽略/不支持的部分 | 后果 |
| --- | --- | --- |
| `awk` | `END` 块**不做算术、不支持 printf** | 错误率算不出来（打印空值） |
| `sed` | 范围 `/起/,/止/` 只认**整串子串**，转义斜杠不生效 | range 恒返回 0 行 |
| `git log` | `--grep` / `--author` / `-- <file>` / `<rev>..<rev>` 全被忽略 | 返回全量日志，筛选无效 |
| `kubectl` | **不支持 `-o json`**（返回表格）；`logs -n` 的选项顺序有要求 | jq 管道直接报错 / 找不到 pod |
| `mysql` | **不装载业务表行数据**（只支持 SHOW / 元数据查询） | `SELECT … FROM orders` 报错 |
| `redis-cli` | `LATENCY` 未实现（已给它一句"用什么替代"的说明） | 提示里提到它会把学员带进死路 |
| `keepalived` | **配置文件根本不存在** | 那条记录的示例跑不了 |
| `helm` | `create/dependency/package/push` 只有教学说明；`--version` 被忽略 | 写课只能用 8 个子命令 |

**写课流程（v3.5 起固定为三步）**：
① 查引擎是否支持该命令**与该参数**（不只是命令名）；
② 把每一步的命令**真跑一遍**，把真实输出写进 `expect`；
③ `node tools/check-all.js` 兜回归。**第 ② 步是新增的，也是全部发现的来源。**

**当前状态：15 项全绿。**

无头浏览器用 Chrome `--headless=new`。**注意三个环境坑**：
1. `--window-size` 给出的视口尺寸与窗口不一致（实测 800 的窗口得到 649 的视口），**不要靠截图判断布局**，要用注入式测量脚本读 `getBoundingClientRect()`。手机视口断言走 CDP 的 `Emulation.setDeviceMetricsOverride`。
2. 冒烟测试从 dump 的 DOM 里抠结果时，正则要精确匹配带 `style="display:none"` 的容器并从最后一次出现处取值——否则会匹配到被内联进页面的测试脚本源码。
3. 链接体检里 **403/418/429/567 不是死链**：`dev.mysql.com` 的 WAF 对脚本一律 403（走 Oracle 镜像代理校验），华为云对 HEAD 返回 567 但 GET 是 200，gnu.org / docker.com / github.com 会限流。工具已把「真死链」与「反爬/限流」分开报，别再把后者当问题修。

## 8. 设计演进的教训（避免重犯）

1. **不要把参考截图当规格说明书。** 最初把一张在线实验平台的实拍图当 1:1 复刻目标，结果连对方的 LMS 功能（学员管理、消息通知、考试系统、XP 进度条）都做了占位——对"学命令"毫无用处，还背上了别人的品牌。后来改成 CloudCmd 自己的练习平台，**只保留"左终端 + 右步骤讲义"这个真正承载学习闭环的结构**。这是正确方向。
2. **"页面能看"不等于"功能能用"。** 本项目抓出的几个同级严重缺陷都是这种类型：
   - 命令报错被静默丢弃（`ls /nope` 什么都不输出、退出码还是 0）→ 学员敲错却得不到反馈
   - 终端没绑上练习（父节点关系变了、`closest()` 取到 null）→ 页面正常但步骤永远不打勾
   - Wrapper 只在首次执行命令时才创建 → 首屏欢迎语孤零零贴在顶部
   **只有行为级断言（"执行第一步后是否打勾"）能抓到这类问题**，肉眼看页面发现不了。
3. **布局问题用 DOM 测量，不要靠截图猜。** 曾照着失真截图去改 CSS，方向完全错了（把侧栏改窄，反而加剧折行）。
4. **数据文件引了 ≠ 数据可用。** 复刻页漏了 `window.CC_DATA = window.CC_DATA || {}` 的初始化，所有 `data/*.js` 静默挂到 `undefined` 上。
5. **（v1.5）"测试通过"不等于"测试有效"。** 内容扩到 822 条后，真正出问题的不是内容，而是**工具与测试自己**：
   - `wire-phase2.js` 的正则会越过分类块去改下一个分类，把没写数据的分类**级联误标成已上线**（页面出现空分类）；
   - `shell-check.js` **从不验证 `steps[].cmd`**，而练习平台恰恰靠执行步骤命令来打勾——步骤跑不通学员就永远卡住，`answer` 对也救不了；
   - 校验器把 `<你的AK>` 这种**正确的安全写法**判成"裸占位符"错误。
   判断测试还活着的标准不是"它是绿的"，而是**"故意改坏一处，它会不会红"**。本轮每修完一处都用这种方式反证过。
6. **写测试也要对现实建模。** 给"步骤命令"加校验时，第一版给每步新建 shell，于是 `cp` 找不到上一步 `touch` 出来的文件，把正常课程误判成失败——真机上学员是在**同一个终端**里一步步做的，测试必须用**累积 shell** 顺序执行才对。
7. **（v1.6）截图先发现问题，DOM 测量再定位原因，最后写一条能卡住它的断言。**
   手机版做完时所有断言都是绿的，但截图一看讲义正文只剩一条缝 —— 因为断言量的是**面板高度**（332px，达标），
   而真正被挤没的是**正文高度**（49px）。纯测量会漏掉"看着就是不对"的问题；纯截图又会因为
   无头浏览器窗口尺寸 ≠ 视口尺寸而误判。两者要配合，最后一定要落成断言。
8. **（v1.6）报错要分类，否则工具会被忽略。** 链接体检第一次跑出 140 个"异常"，
   里面真死链只有 18 个 —— 这样的输出没人会看第二眼。分成「页面真的没了」和
   「对方不让你用脚本访问」之后，那份 18 条清单是可以直接派活去修的。
   **一个会产生大量假阳性的检查工具，等于没有检查工具。**
9. **（v3.4）该拍板的事早点拍板，比反复记录它更省事。**

10. **（v3.4）"输出看着像对"的 bug 最难发现 —— 而照着提示词跑一遍就能抓到。**
    `docker images` 的 `-q / -f / --format` 三个选项被引擎**静默忽略**（传了不报错、也不生效，
    直接返回全表），而手册里明确教了 `docker images -q -f reference=web`。
    发现它的方法不是专门去查，而是**写课时把提示词里教的写法真跑了一遍**。
    所以**"新写一节课"本身就是一次引擎体检** —— 这条比任何静态检查都管用。
