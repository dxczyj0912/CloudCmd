## 1. 版本差异条目里需要人工复核的版本分界

## 2. 示例报错的长尾（`tools/example-check.js`）

并行开发结束时的一次快照：**3236 条示例，跑通约 2000 / 未实现 535 / 跳过 391 / 报错 75~151**。
报错数会在并行改动期间跳动（有模块被写坏时，它的命令会整体变成 "command not found"）。
**以所有 agent 停止改动后再跑一次的结果为准**：

```
node tools/example-check.js            # 人类可读分组报告
node tools/example-check.js --cat shell   # 只看某个分类
```

已确认的长尾类型（每条都要做三选一：**补引擎 / 改内容 / 写进豁免清单并说明理由**）：

| 现象 | 条数 | 归属判断 |
|---|---|---|
| `$(date +%F)`、`$(dirname $0)`、`$(pgrep ... | head -1)` 未展开 | ~6 | **补引擎**：shell 控制流任务已包含命令替换（`$()` 与反引号、可嵌入参数中间、支持管道与嵌套） |
| `[ "$rc" = 124 ]` → `[: command not found` | 2 | **补引擎**：`[` / `test` / `[[ ]]` 在控制流任务范围内 |
| `source: command not found` | 1 | 补引擎（一个小的 `source`/`.` 实现）或改内容 |
| `history 20` / `history \| grep tar` → 引擎抛异常 | 2 | **补引擎**：`history` 带参数时崩（`Cannot read properties of undefined`） |
| `more +100 file`、`tail -n +100 file`、`cat: +F` | 3 | 补引擎：`tail -n +N`（从第 N 行到末尾）与 `more +N` |
| `column: command not found` | 1 | 补引擎（`column -t`）或改内容 |
| `dd if=/dev/sdb`、`dd if=/data/iso/...iso` | 2 | **改内容或补模拟数据**：仿真是文件系统快照，没有块设备 |
| `curl ... download.example.com` | 2 | **改内容或补端点**：curl 端点表里没有这个域名 |
| `kubectl --kubeconfig=./x.yaml get nodes` | 2 | **补引擎**：全局选项出现在子命令**之前**时不被识别 |
| `terraform graph`（在 /root 下跑） | 2 | **改内容**：示例应先 `cd /data/iac` |
| `redis-cli -h cache-prod-01 ... \| xargs ...` | 3 | **写进豁免清单**：输出的是"这台缓存主机不在本机 /etc/hosts 里"的教学提示，属**有意为之** |
| `xargs: mv/ping: command not found` | 2 | 补引擎：`xargs` 只能调用白名单里的命令，需要扩表或给出更清楚的教学提示 |
| `grep: OutOfMemory` / `grep: /var/log/tomcat/` / `sort: /data/tmp: Is a directory` / `diff: unrecognized option` / `jq: Could not open ...` / `cp: cannot stat` / `mv: cannot stat` | 各 1~2 | 逐条判定：多数是**示例本身写错了路径或参数顺序**，少量是引擎选项缺失 |
| `echo "alias ll=..." >> ~/.bashrc && source ~/.bashrc` | 1 | 前半段已修（`resolvePath` 里未定义的 `HOST` 导致**任何带 `~` 的路径都抛异常**，已改为 `BASE_HOST.home`）；`source` 仍需补 |

## 3. 并行开发期间记下的协作教训（下一轮流程要改）

1. **一个模块的半成品会让所有检查假性崩溃。** 十来个工具都逐个 `eval`/`require` 命令模块，
   其中一个语法错，全部工具都报"引擎加载失败"，看起来像遍地是 bug。
   已在 `tools/_cmdlist.js` 加**逐模块语法预检**：跳过写坏的模块并大声警告，其余检查照常跑；
   `tools/syntax-check.js` 仍是硬闸门（check-all 第一项）。
2. **`assets/js/shell.js` 被多个任务同时编辑**（新增模块的作者 vs 已有命令体的作者）。
   已要求：只做定点编辑、每次写入前重读、绝不整文件覆盖。
   下一轮如果还要并行，应把"改 `exec` 链路"与"改命令实现体"排成前后两段，而不是同时。
3. **agent 的自我汇报必须交叉验证。** 本轮抓到 4 处"自测通过但其实是半成品"的情况
   （truncated 文件、重复行、未转义撇号、未加引号的连字符键），全部由独立闸门发现。
