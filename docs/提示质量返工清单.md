# 渐进式提示 · 质量返工清单

> 来源：四份课程文件各自的提示作者在结单时**主动列出的"写得还不够好"的地方**。
> 机器闸门 `tools/hint-check.js` 只管两件事 —— 两级是否齐全、骨架是否是命令的严格变形。
> **它管不了"这条提示对学员是否真的有用"**，所以这份清单必须由人来过一遍。

> 状态：待返工 ｜ 总数 157 步 ｜ 已点名 约 60 步

## 0. 一个格式层面的问题（先定规则，再逐条改）

**问题**：像 `touch` / `cat` / `stat` / `curl` / `rm` / `uptime` / `nproc` / `top` 这类**没有选项**的命令，
在"骨架必须是 cmd 的严格变形、且只挖一处"的规则下，唯一能挖的只有**参数**（文件名、URL），
而这些参数**在任务文本里已经给出**了（"创建 /tmp/demo.txt" → `touch /tmp/____`）。
于是第 2 级必然送分；而第 1 级又被禁止点名命令 —— 这一档步骤的提示质量被格式本身锁死。

**建议的统一改法（需要先认可这条规则）**：

> 无选项命令，**挖命令名本身**，而不是挖已经给过的参数。

| 现在 | 改成 | 学员要回忆的东西 |
|---|---|---|
| `touch /tmp/____` | `____ /tmp/demo.txt` | 哪个命令创建空文件 |
| `curl ____` | `____ http://127.0.0.1` | 哪个命令发 HTTP 请求 |
| `uptime` → `____` | `____`（保持，但概念提示要给判据） | 哪个命令看 1/5/15 分钟负载 |
| `stat /data/app/____` | `____ /data/app/config.yaml` | 哪个命令给 inode 与三个时间 |
| `df ____` | `____ -h /data` | 哪个命令看容量（选项一起挖） |
| `rm /tmp/demo.txt /tmp/____` | `____ /tmp/demo.txt /tmp/note.txt` | 哪个命令删文件 |

`hint-check.js` **已经允许**这么挖（它只要求骨架填通配后能匹配 cmd），所以这是纯粹的文案返工，不用改工具。

## 3. `data/lessons-cloud.js`（30 步）

1. **`git add config.yaml && git status -s`**：空留在 `-s` 上，等于把 `git add config.yaml` 直接给了学员 —— 虽然换来了"两列含义"这个判据，但确实泄了这一步的标题动作。
2. **`jq -r "____"`**：概念提示说了"数组要先展开成逐个元素"，但没点破 jq 的展开记法（`[]`），没接触过 jq 的人会写成 `.servers.name`。
3. **`git log --oneline -3`**：空只是一个数字，是全文件最没概念含量的一个空 —— 概念提示承担的是工作流判据而不是"敲什么"。
4. **`obsutil ... -dryRun`**：概念提示说清了"演练不动对象"，但没给旗标拼写；真 obsutil 大小写敏感，写成 `-dryrun` 在模拟器能过、真机会失败。
5. **`hcloud ECS ListServersDetails`** 在三节里出现三次：分别把空留在操作名与服务码上来避免雷同，但第三遍的增量信息有限。
6. **`git diff` / `git status` / `git push` / `git tag` / `git branch`** 这类单词命令，骨架只能是 `git ____`，信息量低 —— 区分度全靠概念提示。

## 4. `data/lessons-data.js`（40 步）

1. **4 处骨架只剩 `____`**：`uptime`、`nproc`、`top`、`sed -i 's/^}$//' …` —— 因为闸门要求骨架必须含 `____`，这些步骤只能整条 mask，骨架不传递任何结构信息，全靠概念提示。
   → 建议按第 0 节统一处理：这类"整条 mask"应改为**挖命令名**（`____` 保留但概念提示必须给出可操作判据）。
2. **概念提示偏"流程描述"**：`top`（两处）、upstream 改名、两处 `cp` 还原 —— 写成了"改完必须立刻验一次"，信息量低于其它条。
3. **`db-mysql-replica-broken` 第 3 步轻微泄题**：「字段名本身就带 Last 和 Error 字样」已经把 `Last_SQL_Error` 点出来了。
4. **`mw-nginx-bad-conf` 第 1、2 步内容重复**：两处 cmd 都是 `nginx -t`（基线 / 复验），概念提示几乎同义，连做两步会觉得啰嗦。
5. **技术限制（无需返工，但要知道）**：提示里的强调引号统一成了全角 `“”`。原因是 ASCII 双引号在单引号 JS 字面量里的 `\"` 转义会被 `hint-check.js` 的反转义吞掉、进而在页面上丢失；全角是"页面显示有引号"与"通过校验"能同时成立的唯一写法。
