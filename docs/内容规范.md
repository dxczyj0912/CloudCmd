# 内容规范 · CloudCmd 数据录入标准（v3.3）

> 本文件是**数据契约的冻结版本**。所有 `data/*.js` 内容文件必须严格遵守。
> 违反契约会导致站点渲染异常或搜索失效。
>
> **v3.3 增补**（引擎"子集实现"清单 —— 写课前的必查项）：
> - §5.15 新增 **「引擎的'子集实现'：哪些参数会被静默忽略」**：`awk` 的 `END` 块不做算术、
>   `sed` 的范围只认整串子串、`git log` 的 `--grep/--author/-- <file>` 全被忽略、
>   `kubectl` 不支持 `-o json`、`mysql` 不装载行数据…… 并存下**写课三步流程**
>   （查参数级支持 → 真跑一遍取真实输出 → `check-all` 兜回归），
>   以及**"不要为了看起来完整去实现这些命令"**的纪律。
>
> **v3.2 增补**（练习步骤的三条硬约束 —— 都是被 `shell-check` 逼出来的）：
> - §5.14 新增 **「写练习步骤的三条约束」**：
>   ① 每个 step 必须**退出码 0**，而有些命令"正常就该返回非 0"（`kubectl diff` 有差异返回 1、
>   `umount` 报 busy 返回 1）—— 处理方式是**在命令里接一句兜底**，同时把这件事教给学员；
>   ② **`answer` 不能与某个 step 产生同样的副作用**（校验器先跑 steps 再跑 answer，
>   非幂等的 answer 第二次必然失败）；
>   ③ **`expect` 要按引擎的真实输出写**，不能按"真机应该输出什么"想当然
>   （`/proc/<PID>/wchan` 在引擎里是 `ep_poll`，不是 `futex`/`epoll_wait`）。
>
> **v3.1 增补**（检查器的可信度 —— 一条比内容规范更根本的规范）：
> - §5.12 新增 **「检查器不许说假话」**：`example-check` 判"首词是哪个命令"时
>   必须跳 `变量=值` 前缀、且**只跳那些自己没被实现的包装词**；
>   非命令行条目的示例（控制台子命令 / 配置片段）整体跳过
> - §5.12 记下代价：这两处误判曾把"疑似打错"抬到 171 条（其中约 130 条是误报），
>   既让人去修本来没坏的东西，又**低估了可教面**
> - §5.13 新增 **统计口径要先钉死**：判断"示例可不可跑"看的是**跑起来是否报错**，
>   而不是"有没有 stdout" —— `mv`/`cp`/`mkdir`/`chmod` 成功时本来就不打印
>
> **v3.0 增补**（测试隔离 —— 一条容易被忽略但影响很大的规范）：
> - §5.10 新增 **「测试环境也是共享状态」**：`example-check` 用什么粒度跑示例、
>   为什么是"每条命令条目一个 shell"而不是共享或每示例一个
> - §5.10 记下这条规范的由来：**报错栏里的 1/3 曾经是检查器自己制造的假失败**
> - §5.11 新增 **块注释里不要给路径加粗**：`**/etc/shadow**` 里的"星号加斜杠"
>   会提前闭合 `/* */`，导致整个文件语法错误、浏览器白屏（本项目已踩过四次）

## 1. 文件骨架（必须逐字照抄）

每个 `data/<分类id>.js` 只有这一个结构，**不要**用 `export`、`require`、`import`、`const` 顶层声明：

```js
/* data/linux-basic.js · 分类 01 Linux 基础与文件操作 */
(function () {
  'use strict';

  var catId = 'linux-basic';

  window.CC_DATA[catId] = window.CC_DATA[catId] || [];
  window.CC_DATA[catId].push(

    /* ---------- 1 / 60 ---------- */
    {
      id: 'linux-basic-ls',
      name: 'ls',
      alias: ['list'],
      level: 1,
      syntax: 'ls [选项] [文件|目录]',
      summary: '列出目录内容，最基础的查看命令。',
      desc: '默认按名称排序输出，不显示隐藏文件（以 . 开头）。生产上最常用的是 ls -lh 与 ls -lht。',
      params: [
        { flag: '-l', desc: '长格式：权限、属主、大小、修改时间' },
        { flag: '-a', desc: '显示隐藏文件（含 . 与 ..）' },
        { flag: '-h', desc: '人类可读的文件大小（KB/MB/GB），必须与 -l 同用' },
        { flag: '-t', desc: '按修改时间排序，最新的在最前' },
        { flag: '-R', desc: '递归列出子目录' }
      ],
      examples: [
        { cmd: 'ls -lht /var/log', desc: '看 /var/log 下最近改动的文件，排障第一步' },
        { cmd: 'ls -ld /data', desc: '只看 /data 目录本身的信息，而不是目录里的内容' }
      ],
      notes: ['ls 的输出不适合脚本解析，脚本里应使用 find 或 stat'],
      related: ['linux-basic-find', 'linux-basic-stat'],
      docs: 'https://man7.org/linux/man-pages/man1/ls.1.html',
      tags: ['文件', '目录', '查看']
    }

    /* 后续命令同样追加在这里，用逗号分隔 */
  );
})();
```

**要点**：
- 结尾 `push(...)` 的括号内是命令对象列表，**对象之间用逗号分隔，最后一个对象后面不要加逗号**（老浏览器兼容考虑，虽然现代浏览器支持尾逗号，但统一不写）。
- 文件必须能被 `node --check <file>` 通过语法检查。
- 文件必须是 **UTF-8 无 BOM**。

## 2. 字段规范

| 字段 | 必填 | 类型 | 规范 |
| --- | --- | --- | --- |
| `id` | ✅ | string | **全局唯一**。格式 `<分类id去掉linux前缀的简写>-<命令动作>`，见 §3 |
| `name` | ✅ | string | 命令名。带子命令的写全，如 `docker run`、`kubectl get` |
| `alias` | ❌ | string[] | 别名、旧写法、常见误写（用于搜索加权） |
| `level` | ✅ | number | `1` 入门 / `2` 进阶 / `3` 高级 / `4` 专家 |
| `syntax` | ✅ | string | 语法格式，用 `[选项]` `[文件]` 表示可选，`<必填>` 表示必填 |
| `summary` | ✅ | string | **一句话**，20~45 字，说清"它是干嘛的"。禁止以"该命令用于"开头 |
| `desc` | ❌ | string | 补充说明：原理、与其他命令的区别、典型使用场景。**不要复述 summary** |
| `params` | ❌ | object[] | `{flag, desc}`。**只收高频参数，3~6 个为宜**，最多 8 个 |
| `examples` | ✅ | object[] | `{cmd, desc}`，**至少 1 个，建议 2 个**。必须是可直接复制执行的完整命令 |
| `notes` | ❌ | string[] | 踩坑提醒、危险警告。**危险命令必须有** |
| `related` | ❌ | string[] | 相关命令的 `id`（必须是站内真实存在的 id） |
| `docs` | ❌ | string | 官方文档 URL，必须真实可访问 |
| `tags` | ❌ | string[] | 2~4 个中文关键词，补充搜索命中 |

## 4. 内容质量红线

1. **示例必须可直接执行**：不能出现 `xxx`、`your-value` 这类占位符混在命令里。必须用尖括号并说明，如：
   - ✅ `docker run -d --name web nginx:1.25`
   - ✅ `ssh -i ~/.ssh/id_rsa root@<ECS弹性公网IP>`
   - ❌ `ssh root@你的服务器`、❌ `docker run xxx`

2. **禁止编造参数**。不确定的参数宁可不写。官方文档链接必须真实。

3. **危险命令必须有 `notes` 警告**，明确后果：
   - `rm -rf` / `dd` / `mkfs` / `iptables -F` / `chmod -R 777 /` / `kubectl delete` / `docker system prune -a`
   - 例：`notes: ['rm -rf 删除后无法恢复，执行前务必用 pwd 确认当前目录；生产环境禁止对 / 使用']`

4. **区分发行版差异**：CentOS/RHEL 与 Ubuntu/Debian 差异明显的（`yum` vs `apt`、`firewalld` vs `ufw`、`/etc/sysconfig` vs `/etc/default`）必须在 `desc` 或 `notes` 里点明。

5. **中文优先、术语保留英文**：说明用中文，专业术语保留原文（如 `cgroup`、`OverlayFS`、`kubeconfig`）。

6. **行内代码用反引号**：`desc`、`notes` 里提到命令、参数、路径时用 `` ` `` 包裹。

7. **不要复制官方文档原文**。用自己的话写说明，官方文档只放链接。

8. **难度分级参考**：
   - L1 入门：`ls` `cd` `cat` `mkdir` `docker ps`
   - L2 进阶：`find -exec` `sed -i` `systemctl` `docker run` 完整参数、`awk` 条件
   - L3 高级：`iptables` NAT、LVM 扩容、`tcpdump` 过滤表达式、`kubectl patch`
   - L4 专家：内核参数调优、`nsenter` 排障、复杂 `awk`、`kubectl` 高级排错

### 5.3 练习课程与步骤（`data/lessons.js`）

**v2.0 起，一课 = 一个对象，核心是 `steps[]`。**

```js
window.CC_LESSONS = [
  {
    id: 'awk-topip',                    // 全局唯一，用命令/场景的语义命名
    cat: 'linux-text',                  // 属于哪个分类（决定它在分类页「实时练习」入口里出不出现）
    title: '统计访问量最高的 IP',         // 卡片标题
    prompt: '你想知道哪个客户端 IP 请求得最多。',   // 场景描述（讲义顶部）
    task: '统计 access.log 里出现次数最多的前几个 IP', // 本节目标
    steps: [                            // ★ 核心：可勾选的步骤
      { title: '取出第一列', about: 'Nginx 默认格式第一列就是客户端 IP',
        cmd: "awk '{print $1}' /var/log/nginx/access.log", note: '先看看能取出什么' },
      { title: '排序', about: '让相同 IP 挨在一起，uniq 才能计数',
        cmd: "awk '{print $1}' /var/log/nginx/access.log | sort" },
      { title: '计数', about: '统计每个 IP 出现多少次',
        cmd: "awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c" },
      { title: '倒序取前几', about: '得到访问量 Top 榜',
        cmd: "awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -3" }
    ],
    answer: "awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head",
    alt: ["... | head -10"],            // 等价写法，shell-check 会逐个验证
    expect: /203\.0\.113\.25/,          // 输出里必须出现的关键内容（"结果正确"判定）
    teach: '这是运维最经典的一条管道……'      // 讲解，全部步骤完成后展开
  }
];
```

**字段规范**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 全局唯一。**不要带分类前缀**（渲染时会加 `cc-`） |
| `cat` | ✅ | 分类 id，必须是 `_registry.js` 里存在的分类 |
| `title` | ✅ | 卡片标题，动词开头，说清"做什么" |
| `prompt` | ✅ | 场景描述，用第二人称"你"，写出真实处境 |
| `task` | ✅ | 本节目标，一句话 |
| `steps` | ✅ | 至少 2 步。**每步必须有 `title` 与 `cmd`**；`about`（作用说明）与 `note`（要点提示）可选但强烈建议写 |
| `answer` | ✅ | 参考答案（完整命令，通常是把 steps 串起来） |
| `alt` | ❌ | 等价写法数组，**必须都能真跑通**（否则 shell-check 会失败） |
| `expect` | ✅ | 正则，输出里必须出现的内容 —— 用于"结果正确"的判定 |
| `teach` | ❌ | 讲解，全部步骤完成后展开。支持 `**强调**` 与 `\`code\`` |

**写作红线**

1. **`steps[].cmd` 必须是能真跑通的命令**（`shell-check.js` 会按顺序在**同一个累积 shell** 里逐条执行验证）
2. **步骤要由浅入深**：第一步通常先"看看原始数据长什么样"，最后一步才是完整解法
3. **`expect` 不能太宽**：要能区分"做对了"和"命令跑通了但结果不对"
4. **不写 `steps` 的旧课会被自动降级**：按管道/&& 拆 `answer`。但**新内容一律显式写 `steps`**

**⚠️⚠️ Shell 控制流的能力边界（v2.0 大修后逐条实测，写 shell/linux 课之前必看）**

把这一节单列出来，是因为**它曾经害一整节课写不出来**：v2.0 之前
`while IFS= read -r`、数字比较、`$(( ))`、`case`、循环体里嵌 `if` **全都跑不通**
（而且多数是静默给出错结果，不报错），写课的人只能绕路，最后交出一节
"讲了但演示不了"的课。当前能力清单以 `data/lessons-shell.js` 头部注释为准，要点：

| 能力 | v2.0 起 | 备注 |
| --- | --- | --- |
| `for x in <列表 \| 通配符 \| $(命令替换)>`、`{1..5}` | ✅ | 词表里的命令替换先跑，再按 IFS（含换行）切词 |

| `if/then/elif/else/fi`，**可嵌在循环体里** | ✅ | |
| `while` / `until`，含 `done < 文件` 与 `命令 \| while read` | ✅ | |
| `case … in … esac`（通配分支、`a\|b` 多模式），可嵌在循环体里 | ✅ | 分支末尾的 `;;` 不能漏 |
| `break` / `continue` | ✅ | |
| `$(cmd \| cmd)`、赋值 `X=$(…)`（含 `\| wc -l` 这类带空格的输出） | ✅ | |
| 参数展开 `${#V}` `${V#p}` `${V%p}` `${V:-}` `${V:=}` `${V:?}` `${V:+}` | ✅ | `${V:?}` 会真报错并非 0 退出 |

| **管道每段在独立子 shell**（变量改动不回传） | ✅ | **与教材一致**，第 6 课专门讲 |
| `set -- a b c` 与位置参数（`$1` `$#`） | ❌ | 终端里恒为空/0，所以"参数校验"只能练 `${V:?}` |
| 数组、函数、`trap`、进程替换 `<(…)`、here-doc/here-string | ❌ | |
| `done \| 命令`（整条循环的输出接进管道） | ❌ | 循环体内的管道正常，只有"循环整体接管道"不行 |
| `rmdir` | ❌ | 用 `rm -r` 代替 |

**写 shell 课的三条纪律（都是踩过的坑）**：

1. **步骤对象一行一个** —— `tools/hint-check.js` 与 `tools/about-leak-check.js` 共用
   `tools/_stepscan.js` 按行解析；拆成多行会被**整份跳过**，而工具照样打印"全部通过"。
   （这个坑真实发生过：5 节课 23 个步骤显示 `0 / 0 步（0%）` 却报绿。）
2. **每步 `cmd` 都要以 0 退出** —— 像 `grep` 无匹配返回 1、`${VAR:?}` 报错退出这类
   "非零也是结论"的命令，要配 `grep -c` / `\|\| echo …` 让整条落到 0。
3. **`answer` 与 `alt` 必须自包含** —— `shell-check` 验证 `answer`/`alt` 时用的是**全新 shell**，
   不能依赖前面步骤留下的 `/tmp/xxx` 文件；而验证 `steps[].cmd` 时用的是**同一个累积 shell**。

**`cat` 与讲义头部的「场景」名**

`cat` 决定这节课挂到哪个分类的「实时练习」列表里。练习平台讲义顶部显示的**场景名
不再手工维护**：`academy-lab.js` 的 `sceneOf()` 先查少量人工覆盖
（`linux-text`→「Linux 文本处理」这类比注册表更口语化的名字），查不到就回落到
`data/_registry.js` 里的 `name`。因此**新增分类只要注册表里有，场景名就自动正确**；
一旦出现「综合练习」（兜底值），说明该分类没登记进注册表 —— `lab-check.js`
有一条断言专门盯这个。

### 5.5 给模拟引擎加命令（`assets/js/shell.js`）

#### 5.5.1 先分流，再动手 —— 未实现命令的三档处置

「引擎缺 100 多个命令」听起来像一个大工程，实际按**示例依赖的夹具**分流之后，
只有一部分值得实现。动手前先跑一次分档（判据是"记录里的示例引用了哪些**绝对路径**、
其中多少在 termfs 里不存在"）：

| 档 | 判据 | 处置 | 本轮实测 |
| --- | --- | --- | --- |
| **A 档** | 示例**不引用**任何缺失夹具 | **直接实现** —— 实现完示例就从"跳过"变成"真跑" | 53 个；已实现 10 个（`tree nl whereis type egrep fgrep column chown chgrp getent`）→ 示例跑通 +25、`未实现命令` −24 |
| **B 档** | 示例引用了缺失夹具（`/data/iso/*.iso`、`/data/img/*.qcow2`、`/data/app/current` 软链…） | **先补夹具再实现**。用 `window.CC_SHELL.fsAdd({...})` 写在任意模块里，父目录自动创建、同名先到先得 | 72 个 |
| **C 档** | 真实网络 / 内核操作 / 交互式程序 / 需要真实软件源，**按设计不做** | **只补一句原因**到 `assets/js/shell.js` 的 `NOT_IMPL`，页面会照实显示 | 22 个，其中 7 个已写原因 |

**为什么必须分流**：`example-check` 对"引擎未实现"的命令是**跳过**（不算失败），
而一旦实现，它的示例就变成**真跑**。所以 B 档命令若不同时补夹具，
结果是**把"跳过"变成"失败"** —— 数字上更难看，而且掩盖真问题。

**⚠️ 未实现清单里混着"根本不是命令"的条目**：手册里有 42 条记录的名字是小写的
Ansible 模块 / Terraform 关键字 / 配置文件名 / sysctl 键
（`copy`、`template`、`when`、`register`、`region`、`variable`、`daemon.json`、
`compose.yaml`、`net.core.somaxconn`、`pg_stat_activity`…）。
**它们不该被实现，也不该在页面上被标"跑不了"** —— 判据不用启发式，用数据自己说话：
> 记录的 `syntax` 首词必须与 `name` 首词一致，才说明这条记录描述的是一条命令行。
> `tree [选项] [目录]` ✓ ｜ `region = "cn-north-4"` ✗ ｜ `- ansible.builtin.copy: {...}` ✗

这条判据写在同一处（`render.js` 的 `runnability()`），并配了一条**防假阳性断言**
（`SHOW`/`Pod`/`LVM`/`华为云`/`autofs`/`when` 这些必须**不出现**提示）。

**⚠️ 还有第三类：配置指令 / SQL 语句。** 手册里有一批记录描述的是"某个配置文件里
该怎么写"，首词恰好也是小写 ASCII：

```
location [ = | ~ | ~* | ^~ ] <匹配模式> { ... }      ← nginx 配置指令
proxy_pass <http://上游名或IP:端口>[URI];            ← nginx 配置指令
locals { <名字> = <表达式> }                        ← Terraform 块
SHOW PROCESSLIST;                                  ← SQL 语句
```

判据（**先剥引号、再剥 `#` 注释**）：含块语法 `{` 或以 `;` 结尾 → 视为配置条目，不给提示。
剥注释这半步是必需的 —— `client_max_body_size <大小>;   # 可写在 http 块`
这种"syntax 里带说明注释"的条目，不剥注释就会漏网。

**这三类假阳性是连续三轮各发现一类的**（v2.1 的 `for` 复合行、v2.2 的非命令条目、
v2.4 的配置指令），规律完全一样：
**判据只要用"看起来像"的启发式，就一定会误伤。**
唯一稳的做法是**用数据自己的结构说话**（`syntax` 首词一致、块语法、语句终止符），
并且**每条判据都配一个反向断言** —— 真命令必须仍然拿到提示，
否则判据可能宽到把该标的一起吞掉。

#### 5.5.2 夹具模块：命令与夹具必须一起上

`assets/js/fs-extra.js` 是**教学夹具**的集中地（用 `CC_SHELL.fsAdd` 挂载，父目录自动创建、
**同名先到先得**，所以永远不会覆盖 termfs 里的东西）。它存在的原因是一条硬约束：

> `example-check` 对"引擎未实现"的命令是**跳过**（不算失败），
> 一旦实现了那条命令，它的示例就变成**真跑**。
> 所以给 B 档命令补实现时**必须同时补它示例依赖的夹具**，
> 否则结果是**把"跳过"变成"失败"** —— 数字更难看，还掩盖真问题。

**补夹具时最容易忽略的一点：夹具要满足整条"剧情线"，不只是单条示例。**
真实踩到的例子：`lb-ln` 的示例会把软链 `current` 切到 `v1.2.0` / `v1.3.0`
（`ln -s`、`ln -sfn`），而后面 `lb-readlink` 的示例要求 `current/conf/app.yml`
**真实存在** —— 只建 `v2.3.x` 就会连环失败。同理 `lb-xz`/`lb-zstd`/`lb-gunzip`
在同一个备份文件上做"压缩 → 校验 → 解压"，夹具的初始状态必须让整串命令都能跑完。

**两条实现纪律**（写进 `cmd-basic3.js` 与 `cmd-host.js` 的头部注释）：
1. **不假装**：压缩族不编造压缩比（只翻 `gz` 标记 + 改名）；
   `zip`/`unzip` 用自描述内部格式，保证**真能往返**，而不是固定假输出。
2. **会改主机状态的命令真改**（主机名/时区/locale/umask），改完必须能用另一条命令验证 ——
   `hostnamectl set-hostname` 要同步 `/etc/hostname`、`umask` 要影响 `touch`/`mkdir` 的默认权限；
   **会关机的命令绝不假装成功**（`shutdown`/`halt`/`poweroff`/`reboot`）——
   假装"已关机"会让学员低估这条命令的杀伤力，正确做法是说清不会执行 + 讲透参数与取消逻辑。

**⚠️ 未实现原因文案的写法要求**（`assets/js/shell.js` 的 `NOT_IMPL` /
`SHELL_EXTRA_UNSUPPORTED` 两张表，页面与终端共用）：

> **"未实现"三个字是最没用的反馈。** 每条原因必须落到三者之一 ——
> **① 为什么不做**（真实网络 / 内核操作 / 交互式程序 / 需要真实软件源）、
> **② 去哪儿学**（指向站内哪一条目）、
> **③ 用什么替代**（给出**可执行**的等价命令）。
>
> 判断标准很朴素：**学员看完这句话，知不知道下一步该干什么。**

正例：`rg` 不可用 → "真机上要 `yum install ripgrep`；它 90% 的用法就是 `grep -r` 的加速版，
本站 `grep -r` 已实现，`-i/-n/-l/-c/-A/-B/-C/--include` 全都有"。
反例：`rg: 教学环境未实现该命令。`

当前会给「仅真机」提示的 **60 个命令全部**有具体原因，平均 **115 字**；
`tools/shell-check.js` 与 `render-check` 的断言会检查"页面确实引用了引擎登记的原因"。

**另：两张表要一起维护。** `notImplementedReason()` 必须同时查 `NOT_IMPL` 与
`SHELL_EXTRA_UNSUPPORTED` —— 早先只查前者，于是 `trap`/`bash`/`nohup` 在
**终端里有解释、命令详情页却退化成兜底文案**，同一件事两种说法。

### 5.10 测试环境也是共享状态

**`tools/example-check.js` 的隔离粒度是"每条命令条目一个 shell"，不要改。**

它曾经用**一个共享 shell** 跑完全部 3000+ 条示例，后果是**报错栏里约 1/3 是检查器
自己制造的假失败**：像

```
mv  /var/log/nginx/access.log /var/log/nginx/access.log.$(date +%F) && nginx -s reopen
rename .log .log.bak /data/app/logs/*.log
gzip -9 /data/backup/db.sql
```

这些示例**完全正确、而且本来就是这么用的**——它们的动作就是"把文件改走"。
但在共享 shell 里，排在它们后面的示例还要读同一个文件，于是报
`cat: /data/app/logs/app.log: No such file or directory`。
**真正的缺陷被淹没在这些噪音里**，而"报错 N 条"这个数字也失去了意义。

粒度是实测选出来的（同一次运行比较三种）：

| 粒度 | 报错数 | 说明 |
| --- | --- | --- |
| 共用一个 shell | 38 | 破坏性示例误伤后面的示例 |
| **每条记录一个 shell** | **32** | ← 采用 |
| 每条示例一个 shell | 48 | 把"记录内接力"的正常叙事判成缺陷 |

为什么不是"每条示例一个"：**同一记录里的示例本来就是接力的**
（ex1 `cp` 出文件、ex2 再 `diff` 它；ex1 建 md5 清单、ex3 用 `-c` 校验），
全拆开等于把正常叙事判成缺陷。隔离到**记录**这一级刚好：记录内共享状态，跨记录绝不互相影响。

**同一个道理也适用于写内容**：`data/*.js` 里的示例会在**同一个终端里被依次敲**，
所以**一条示例的副作用会改变下一条的运行环境**。写示例时问自己两件事：

1. **这一步会改走/删掉/改名什么？** 后面还有示例要读它吗？
   （真实案例：`mw-nginx-log` 的"切割日志"排在"分析日志"前面 → 分析那条跑不通。
   调换顺序即可，而"先分析、后切割"本来就符合真实运维习惯。）
2. **它依赖前面某一步留下的状态吗？** 如果是，那两步要么在同一记录内相邻，
   要么应该各自准备好自己的输入（例如把两列各落一个文件，而不是依赖上一步的中间产物）。

**这是 §6.5 第 66 条（断言污染）的同一类问题**：测试环境是共享状态，
写断言、写示例时都必须想着副作用。

### 5.11 块注释里不要给路径加粗

```
/* 说明：**/etc/shadow** 的权限必须是 000     ← 这个 `**/` 会提前闭合块注释！
   于是整个文件语法错误、浏览器白屏。 */
```

`**` 与紧跟其后的 `/` 拼成了 `*/`。**本项目已经踩过四次**（`List*/Show*`、
`batch-*/`、`**/etc/shadow**`、`**/*.log`）。写块注释时：

- 路径、通配符、命令名**一律不要用 `**…**` 加粗**；
- 需要强调就用「」或直接叙述；
- 实在要写 `*/`，改成 `星号加斜杠` 这样的文字，或拆成两行。

`tools/syntax-check.js` 会在提交前拦住它（`Unexpected token` / `Invalid or unexpected token`），
所以**改完 data 与 assets 下的任何文件都要跑一次语法体检**。

### 5.12 检查器不许说假话

**这一条比内容规范更根本**：检查器的输出本身也是"教学内容" ——
它说假话的代价是**让人去修本来没坏的东西，同时看不见真正坏的东西**。

`tools/example-check.js` 判断"这条示例的首词是哪个命令"时，有三条规则必须同时成立：

**① 要跳 `变量=值` 前缀。**
真 shell 里 `ETCDCTL_API=3 etcdctl endpoint health` 是合法写法（给这一条命令临时设环境变量），
站内 etcdctl 一族 7 条记录全这么写。不跳就会把 `ETCDCTL_API=3` 当成命令名。

**② 只跳"自己没被实现"的包装词。**
`sudo` / `time` / `nohup` / `env` / `watch` / `nice` / `xargs` 这几个前缀词性质不同：

| 词 | 在本引擎里 | 该不该跳 |
| --- | --- | --- |
| `time` / `nohup` / `env` / `nice` | 未实现 | **跳**（真命令在后面） |
| `watch` / `xargs` / `sudo` | **已实现** | **不跳**（它们自己就是命令） |

无条件跳的后果：`watch -n 1 "df -h /data"` 的首词被算成 `-n`，
`xargs -I {} mv {} /dst/` 被算成 `-I`，`sudo -l` 被算成 `sudo: -l` ——
三条**完全正确**的写法被归进"疑似打错"。

**③ 非命令行条目的示例整体跳过。**
判据与 `assets/js/render.js` 的 `runnability()` 同一套：

> `syntax` 的首词必须等于 `name` 的首词，才说明这条记录描述的是一条**命令行**。

`obsutil ls` ✓ ｜ `arthas`（syntax 是 `java -jar arthas-boot.jar 然后 dashboard / thread / watch / jad`）✗

典型受害者是 `arthas`：它的 examples 是**它自己控制台里的子命令**
（`dashboard` / `thread -n 3` / `watch <类> <方法>`），其中 `watch` 与 shell 的 `watch` 同名，
于是检查器**真的去跑它**，在"报错"栏留下一条**假缺陷**。

**修完的实测效果**：报错 38→0 之后，本轮又把"疑似打错"从 **171 条降到 41 条**
（约 130 条是上述两类误报）。**而这两个数字此前一直在误导排查方向。**

### 5.13 统计口径要先钉死，再谈数字大小

给"课程还能补多少节"这类问题上限时，**判据本身要先能被检验**。本轮踩到的三个口径错误：

| 错误口径 | 后果 | 正确做法 |
| --- | --- | --- |
| 要求示例**必须有 stdout** 才算"可跑" | `mv`/`cp`/`mkdir`/`chmod`/`chown` 这些**成功时本来就不打印**的命令全被判成不可跑，**低估**可教面 | 看**跑起来是否报错**；有没有输出只是"这一步够不够直观"的质量信号 —— 课里写 `chmod 600 私钥 && stat -c "%a" 私钥` 就能把静默变成证据 |
| 把 `VAR=值 cmd` 的首词算成 `VAR=值` | 7 条 etcdctl 记录白白算成"没有可跑示例" | 跳赋值前缀 |
| 把控制台子命令当 shell 命令 | `arthas` 的 `watch` 被真跑，产生假缺陷 | 非命令行条目整体跳过 |

三处偏差**方向都不一致**（两处偏小、一处偏大），修完是 561 条 / 约 219 节，
与最初估的 189 节相差 16%。**先钉口径，再报数字。**

### 5.14 写练习步骤的三条硬约束

`tools/shell-check.js` 会**真的执行**每节课的每个 `step.cmd` 以及 `answer` / `alt`。
以下三条是写课时必须遵守的，全部是撞过墙总结出来的：

**① 每个 step 必须退出码 0 —— 但有些命令"正常就该返回非 0"。**

| 命令 | 什么情况返回非 0 | 这正常吗 |
| --- | --- | --- |
| `kubectl diff -f` | 有差异时返回 1 | **正常**，CI 门禁正是靠它 |
| `umount` | 挂载点忙时返回 1 | **正常**，是在如实报错 |
| `grep` | 没匹配到返回 1 | **正常**，是 shell 惯例 |

处理方式是**在命令里接一句兜底**，把"非 0 是正常的"这件事**教给学员**：

```js
cmd: 'kubectl diff -f /data/k8s/deploy.yaml || echo "（退出码 $? = 有差异）"'
```

不要为了让步骤通过而**换一条语义不同的命令** —— 那会把教学点一起换掉。

**② `answer` 不能与某个 step 产生同样的副作用。**

校验器先跑 steps、再跑 answer。所以如果某一步是"创建资源"，
而 answer 又是同一条创建命令，第二次执行必然报"已存在"。
真实踩过的例子：把 `docker network create appnet` 当 answer ——
step 2 已经建过它了。

**answer 要选只读的那一步**（`docker network inspect appnet` 就对了）。

**③ `expect` 要按引擎的真实输出写，不能按"真机应该输出什么"想当然。**

踩过的例子：`/proc/<PID>/wchan` 在真机上常见 `futex` / `epoll_wait`，
而模拟引擎给的是 **`ep_poll`** —— 断言里的 `epoll` 匹配不上 `ep_poll`（中间是下划线）。
写 `expect` 之前**先跑一遍看真实输出**，别凭印象写正则。

```js
CMDS.命令名 = function (argv, ctx, stdin, HOST) { ... };
```

| 形参 | 内容 | 用法 |
| --- | --- | --- |
| `argv` | 参数数组（已去引号） | `argv[0]` 是子命令 |
| `ctx` | `{ root, cwd, env, host }` | 读 `ctx.cwd`、`ctx.env` |
| `stdin` | 上一条命令的输出行数组（管道用） | 没接管道时是 `null` |
| `HOST` | **本实例的机器环境**（见 §5.6） | 网卡/网关/DNS 一律从这读，不要写死 |

**返回值**必须用引擎提供的构造器：

```js
return ok(['第一行', '第二行']);           // 成功，退出码 0
return fail(['error: 出错了']);             // 失败，退出码 1，走 stderr
return { out: [...], err: [...], code: 2 }; // 需要自定义退出码时
```

**三条经验**（都是踩过的坑）：

1. **报错要 `fail()`，不要只是不输出** —— 学员敲错了必须有反馈
2. **合并写法要处理**：`-tulnp` `-sh` `-rn` 这类要按字符拆开解析，不能只匹配单字符
3. **加完命令必须在 `tools/shell-check.js` 里补断言**，否则等于没验证

**两条更隐蔽的坑**（2026-09 加 `mysql`/`nginx` 时才暴露出来，属于引擎既有缺陷）：

4. **引号里的 `>` 不是重定向**。`mysql -e "select id from t where time > 100"` 里的 `>`
   被重定向解析器当成了写文件，整条 SQL 会被悄悄吞掉。解析重定向时必须先跳过引号内的内容。
5. **管道里 `2>&1` 的作用域**。`cmd1 2>&1 | cmd2` 里的 `2>&1` 只应该影响 `cmd1` 那一段，
   早期实现让 `mergeErr` 被后续段覆盖，导致只有最后一段的错误会合并。写练习课时
   `nginx -t 2>&1 | tail -2` 这类写法很常用，错了会得到似是而非的输出。

### 5.15 引擎的"子集实现"：哪些参数会被静默忽略

**写课前的必查项。** 引擎实现的是**命令的子集**，而且不只是"少了几个命令"——
**很多命令实现了、但某些参数被悄悄忽略**。2026-09 补 20 节课时一次性抓到 8 个这样的缺陷，
它们此前躲过了全部 15 项检查，原因是**它们不报错**：

| 命令 | 被忽略/不支持的部分 | 症状（看起来很正常） |
| --- | --- | --- |
| `awk` | `END` 块**不做算术、不支持 `printf`** | 错误率算不出来，`printf` 打印空值 |
| `sed` | 范围 `/起/,/止/` 只认**整串子串**匹配，转义斜杠不生效 | range 恒返回 0 行 |
| `git log` | `--grep` / `--author` / `-- <file>` / `<rev>..<rev>` **全被忽略** | 返回全量日志，"筛选"无效 |
| `kubectl` | **不支持 `-o json`**（返回表格）；`logs -n` 的**选项顺序**有要求 | jq 管道报 `Cannot parse as JSON` |
| `mysql` | **不装载业务表行数据**（只支持 `SHOW` / 元数据查询） | `SELECT … FROM orders` 直接报错 |
| `redis-cli` | `LATENCY` 未实现 | 提示里提到它会把学员带进死路 |
| `helm` | `create/dependency/package/push` 只有教学说明；`--version` 被忽略 | 只能用 8 个子命令写课 |
| `keepalived` | **配置文件根本不存在** | 该记录的示例跑不了 |

**为什么"参数被静默忽略"比"命令未实现"危险一个数量级**：
未实现会报 `command not found`，学员**立刻知道**自己敲错了；
而参数被忽略时**输出看起来完全正常**，只有对照"这条命令本该输出什么"才能发现。
**它会同时污染教材**：如果 `expect` 也是照着"看起来正常的输出"写的，
那这个错误就被固化进课程里了（`expect` 与实现**在两边都不算错**的情况下对不上）。

**因此 v3.5 起的写课流程固定为三步**：

1. **查**：引擎是否支持该命令**与该参数**（不只是命令名）——§5.11「引擎模块化」与
   `window.CC_SHELL.runnable(name)` 只能回答"命令名在不在"，**参数级差异必须靠实测**。
2. **跑**：把每一步的命令**真跑一遍**，把**真实输出**写进 `expect`（与 §5.14 第 ③ 条同源，
   但这里更强：不是"别凭印象写正则"，而是"必须真的执行过"）。
3. **兜**：`node tools/check-all.js` 守住回归。

**第 2 步是新增的，也是上述 8 个缺陷的全部来源。**
一个可复用的做法：把待写的命令攒成一个小 JSON，用一个临时脚本一次性跑完并打印
`code / out / err` —— 比在浏览器终端里一条条敲快得多，也避免"看漏了 stderr"。

**另一个同等重要的纪律：不要为了"看起来完整"去实现这些命令。**
本站对 182 个"数据里提到过但跑不了"的命令**逐条登记了拒绝理由**
（`CC_SHELL.notImplementedReason()`），例如：

- `lsattr` / `getfacl` / `ethtool`：**读了只能返回空或编造**，属于"假装成功"，宁可不做
- `useradd` / `passwd` / `iptables` / `chattr`：**会写真实系统或安全边界**，风险高
- `at` / `cron`：**没有守护进程**，提交了也不会跑，"假装已排定"就是骗人

**"诚实地说不支持"比"假装支持"更有教学价值** —— 这条与 §5.12（检查器不许说假话）是同一条原则，
只是作用对象从检查器换成了引擎。

### 5.6 两条硬规则

**规则一：步骤保留（`--previous` 之于 K8s，等价于"步骤不可回退"）**

练习平台的 `bindPanel()`（临时 Shell 面板）产生的会话 **`lesson: null` 且不进 `sessions` 数组**。
这是刻意的：**随便敲命令不能污染步骤判定**。如果你新写的终端绑定逻辑把面板会话也塞进 `sessions`，
学员在面板里敲一条 `docker ps -a` 就会把别处的练习步骤点亮。

**规则二：环境覆盖（一台机器一份环境）**

主站与练习平台的"机器"不同，靠 `CC_SHELL.create(hostOverride)` 隔离：

```js
// 主站：默认环境（EulerOS / eth0 / 10.0.1.23）
var shell = window.CC_SHELL.create();

// 练习平台：声明自己那台机器（Rocky / ens160 / 192.168.17.10）
var shell = window.CC_SHELL.create({
  hostname: 'cloudcmd-lab01', ip: '192.168.17.10', gateway: '192.168.17.1',
  dns: ['114.114.114.114', '223.5.5.5'],
  nic: { name: 'ens160', mac: '00:0c:29:8f:3a:21', cidr: '192.168.17.10/24', brd: '192.168.17.255' }
});
```

**每个实例克隆一份环境，实例之间互不污染**。写新命令时读 `HOST.xxx`（形参），
**不要在模块级写死 IP/网卡名**，否则两个页面会串味。

### 5.7 每日一练卡片（`data/cards*.js`）

**契约与质量样板在 `data/cards.js` 顶部注释里** —— 扩写卡片前先读它。
这里只强调三条最容易写错的：

**① 不要做"命令名 → 中文"的卡。**
单词是「符号 ↔ 含义」的映射，记住就等于学会；命令不是。
「`du` → 查看目录占用」刷三遍就永远不会忘，但它**不会让你在磁盘满的时候想起 `du -sh *`**。
三种卡型都必须是"判断"而不是"认字"：

| kind | 正面 | 背面 |
| --- | --- | --- |
| `diagnose` | 现象（用用户的话说，**不要出现答案里的命令名**） | 该敲什么 + **判据** + 反向排除 |
| `distinguish` | 一组容易搞混的用法 | 分界在哪、什么时候用哪个 |
| `syntax` | 挖了空的命令 | 答案 + 为什么是这个参数 |

**② `contrast`（反向排除）是卡片最值钱的部分。**
它练的是"分诊"：现象不是这样就该往哪想。只写 `why` 不写 `contrast`，
卡片就退化成一条加了壳的 `summary`。

**③ 引擎实现过的命令一定要填 `run`。**
背面带一个「送进终端跑一遍」，是这个项目相对 Anki / 百词斩 的**唯一优势** ——
别的背单词 app 只能给你"释义"，这里能给你真实的命令输出。能用不用，等于白做。

**校验**：`node tools/card-check.js`
它除了查结构，还会把每张卡的 `run` 真丢进引擎跑一遍，并检查
`cmdIds` / `lesson` 引用是否存在、"正面有没有泄露答案"、"`why` 是不是太薄"。

## 5.8 渐进式提示（`hint`）—— 每步两级

学员卡住时，如果只有「看答案」和「放弃」两个选项，教学就断在这里了。
所以**每个步骤都要有两级提示**：

```js
{ title: '按修改时间倒序', about: '最近改动的排最前', cmd: 'ls -lht /var/log/nginx',
  ref: 'lb-ls', hint: ['……', '……'], note: '最近改动的排到最前面' },
```

| 级别 | 字段 | 写什么 | 硬约束 |
|---|---|---|---|
| 第 1 级 | `hint[0]` | **概念提示**：点破思路或判据，给一个抓手 | 10~90 字；不许写出命令（不能出现「命令名 + 空格」）；不许出现完整 `cmd`；不许有 `____` |
| 第 2 级 | `hint[1]` | **命令骨架**：`cmd` 的严格变形，只把这一步真正要学的那一段换成 `____` | 必须含 `____`；把 `____` 换成通配后必须与 `cmd` 全串匹配 |
| 第 3 级 | 无数据 | 直接显示 `cmd` | 由渲染层给，不需要写 |

**为什么骨架必须是严格变形**：如果骨架随手写，学员照着填完跑不通，
提示本身就成了新的坑。`tools/hint-check.js` 会用正则把这件事钉死。

写法对比：

- ✗ `查看文件`（等于没说）
- ✗ `用 ls 命令看看`（直接把命令给了）
- ✓ `要同时看到权限、属主和时间，ls 里哪个选项负责"长格式"？`

**渲染位置**：练习平台 `academy-lab.html` 的**练习模式**（讲义顶部开关）。
打开后命令被模糊遮住，每步出现「💡 提示」「显示答案」两个按钮，点一次给一级。

**校验**：`node tools/hint-check.js`（覆盖率为 0 或骨架对不上都会非零退出）

## 5.9 命令回指（`ref`）与配方标记（`kind`）

这两条是**连贯性**的地基 —— 没有它们，课程、命令手册、练习卡是三座孤岛。

### `ref`：每个步骤回指一条命令条目

```js
{ title: '看清目录里有什么', about: '列出 /var/log/nginx', cmd: 'ls /var/log/nginx', ref: 'lb-ls', note: '…' }
```

- `ref` 必须是 `data/*.js` 里真实存在的 `id`（**不是**命令名）
- 有了它才能：讲义里每步显示「📖 手册」链接、命令页反查"这命令在哪课教过"、卡片回指课程
- 允许跨分类引用（`cloud-cli` 的课讲到 `echo` 的重定向很正常），只统计不报错
- 批量回填：`node tools/wire-continuity.js`（幂等，已存在的不动）

### `kind: 'recipe'`：主题/组合条目不是命令

`awk + sort + uniq 统计 Top IP`、`华为云 ECS 挂载 EVS 数据盘全流程`
这类条目的 `name` 是**中文主题**，不是一条命令。它们会在命令手册里把定位搞模糊，
所以要打上标记：

```js
{
  id: 'lt-nginx-top-ip',
  name: 'awk + sort + uniq 统计 Top IP',
  kind: 'recipe',          // ← 有中文名就必须有它，两者必须同时成立
  …
}
```

判定规则（校验器强制）：`name` 含中文 ⟺ `kind === 'recipe'`。
渲染上：命令手册只列纯命令，配方在单独版块；`ref` 指向配方也是允许的。

**校验**：`node tools/wire-continuity.js --check` + `node tools/continuity-check.js`

### 5.9.1 故障剧本（`data/cheat.js`）—— 连贯性的最后一环

链条「路线图 → 课程 → 命令 → 卡牌 → 配方 → **故障剧本**」的最后一环。
每条剧本是"一个现象 → 一条按排查顺序排好的命令链"：

```js
{
  id: 'cheat-disk-full', group: 'Linux 系统', sym: '💾', level: 2,
  title: '磁盘满（df 显示 100%）',
  cmdIds: ['ls9-df', 'ls9-du', 'mo-lsof', 'lb-find'],   // ★ 由工具生成，不要手写
  chain: ['df -h', 'df -i', 'du -sh /* 2>/dev/null | sort -rh | head -10', …],
  note: '**关键分叉**：先 `df -i` 看是不是 inode 用满…'
}
```

**`cmdIds` 由 `tools/wire-cheat.js` 生成，不要手写、也不要手改** —— 它的匹配规则是
「条目名必须整条是链上行的前缀」（最长前缀优先，同样长时优先 `kind: 'recipe'`），
只在"仅按首词命中且候选唯一"时兜底。改了 `chain` 或命令条目之后重跑一次即可：

```bash
node tools/wire-cheat.js            # 写入（幂等）
node tools/wire-cheat.js --check    # 只读校验（已接入 check-all）
node tools/wire-cheat.js --loose    # 列出"仅按首词兜底"的配对，人工复核用
```

**写作红线**：

1. `chain` 里每一步要么是**真命令**，要么是 `#` 开头的说明行（页面会把说明行单独标出来，
   不当命令看）。不要写"看看日志"这种没有命令的步骤 —— 学员没法照着敲。
2. **跑不了的步骤不用回避**（`ssh`/`iptables`/`chroot` 这些真实网络与内核操作本来就该出现在
   故障剧本里），但页面会按引擎状态自动标「仅真机」。前提是该命令在引擎的 `NOT_IMPL`
   表里**登记过原因** —— 只标一句"跑不了"没有价值，要写清**为什么**。
   新增这类命令时顺手往 `assets/js/shell.js` 的 `NOT_IMPL` 里补一句原因。
3. 一条链路的命令要**按排查顺序**排（先看全局再看细节、先无损再有损），
   最后一条通常是"确认修好了"。

**校验**：`node tools/wire-cheat.js --check` + `node tools/continuity-check.js`（含硬约束）

## 5.11 引擎模块化：命令实现不再挤在一个文件里

`assets/js/shell.js` 已经七千行。新命令实现写到 `assets/js/cmd-<组>.js`，
由 `index.html` / `academy-lab.html` 在 `shell.js` **之后**加载：

```js
(function () {
  'use strict';
  if (!window.CC_SHELL || !window.CC_SHELL.extend) return;
  var U = window.CC_SHELL.util;      /* ok / fail / resolvePath / findNode / readFileOrErr / splitLines / … */
  window.CC_SHELL.extend({
    'virsh': function (argv, ctx, stdin, HOST) { return U.ok([…]); }
  });
  /* 本命令组需要的模拟文件也写在自己文件里，父目录会自动创建 */
  window.CC_SHELL.fsAdd({
    '/data/images/rocky9-base.qcow2': { content: '<binary>qcow2-1.2GB', size: 1288490188, mode: '644', user: 'root', mtime: '2024-03-10 11:20' }
  });
})();
```

四条硬规则：

1. **签名固定** `function (argv, ctx, stdin, HOST)`。`argv` 已分词、glob 与变量已展开。
2. **返回** `{ out, err, code }`；错误必须走 `err` —— 塞进 `out` 会让学员以为报错是正常输出。
3 `extend` **只添加不覆盖**已存在的命令；要改已有命令的行为，改 `shell.js` 里那个函数体本身。
4 新增模块后要同步三处：`tools/_cmdlist.js`、`index.html`、`academy-lab.html`（顺序必须一致）。

**校验**：`node tools/syntax-check.js`（语法错了整站白屏）+ `node tools/example-check.js`

## 6. 新增一个分类：只有三步（用工具，别手改）

一个分类要真正上线，必须同时满足三件事。**漏掉任何一件，侧栏点了没反应或页面是空的**：

1. `data/_registry.js` 里该分类的 `status` 从 `'soon'` 改成 `'ready'`
2. 存在 `data/<分类id>.js` 且条数 > 0
3. `index.html` 的 `<script>` 列表里引入了该数据文件（插在 `data/termfs.js` 之前）

后两步都是机械劳动，用现成工具做：

```bash
node tools/wire-phase2.js --check   # 只看状态，不改文件：列出每个分类的条数
node tools/wire-phase2.js           # 接线：改 status + 注入 <script>
```

工具只处理"文件存在且条数 > 0"的分类，没写好的自动跳过，**可以反复跑**（幂等）。
若还要给这个分类配练习课，见 §5.3；配好后别忘了跑 `lab-check.js`。

> ⚠️ 不要用「`id: 'x'` 之后 600 字内的第一个 `status: 'soon'`」这类正则去批量改注册表：
> 某个分类已经是 `ready` 时，这个正则会**越过自己的块**改掉下一个分类的状态，
> 级联下去会把还没写数据的分类误标成 ready。工具里已按"分类对象块"边界处理。
