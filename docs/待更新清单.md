### U 轮的方法论

**"先实测引擎行为，再写课"是这一轮最有价值的收获。** 本轮 8 个静默缺陷**全部**是写课时
把命令真跑一遍抓到的 —— 而它们此前躲过了全部 15 项检查。原因是它们**不报错**：

- `helm template --set image.tag=1.3.0` 渲染出来还是 `1.2.3`（夹具的 tag 覆盖了显式值）
- `helm status myapp --revision 2` 输出一切正常，但 `REVISION:` 那行写的是 3
- `xargs redis-cli -h H -p 6379 TYPE {}` 报 `unknown command '6379'`（`-p` 被 xargs 吃掉）

**这类"参数被静默忽略"比"命令未实现"危险一个数量级**：未实现会报 `command not found`，
学员立刻知道自己敲错了；而参数被忽略时**输出看起来完全正常**，
只有对照"这个命令应该输出什么"才能发现。

**因此 v3.5 之后的写课流程固定为三步**：① 查引擎是否支持该命令与**该参数**（不只是命令名）；
② 把每一步的命令**真跑一遍**并把真实输出写进 `expect`；
③ 用 `check-all` 兜住回归。**其中第 ② 步是新增的，也是本轮全部发现的来源。**

**另一条体会**：**"我报告的缺口"本身也需要复核。** U10 那条（路线图课程数）我连续两轮
把它当成待办，直到写 C1 时才发现它早就实现了。**报缺口之前先 grep 一遍代码** ——
成本几秒，能避免把已经做完的事反复写进"下一步"。

### T 轮的方法论

**第 ③ 处失败最能说明问题。** 备用答案写的是 `docker rmi $(docker images -f dangling=true -q)` ——
这是**手册里原样教过的写法**，语义上完全正确；而 `expect` 断言的是 `Untagged|Deleted`，
也是**真机一定会打印的东西**。两边都不算错，但**引擎没有真实删除行为**（它如实返回一句
"教学环境不会真的改动容器状态"），于是断言必然匹配不上。

这类对不上的根因是：**断言写的是"语义上应该发生什么"，而不是"这个引擎实际会发生什么"。**
修法不是让断言变松（那是把检查器弄瞎），而是**换一个引擎真有的东西去断言** ——
`<none>` 悬空镜像与具体镜像 ID 都是引擎真实输出的，既保住了强度，也不再依赖仿真里不存在的副作用。

**这一轮还暴露了一条更值钱的线索**：T3 那个 bug 是**"输出看着像对的"**的典型 ——
`docker images -q` 返回了一张完整的表格，没人会觉得它报错，但**它承诺的"只出 ID"没有兑现**。
只跑一遍命令、不看提示词，是发现不了的。**发现它的方法恰恰是"照着提示词里教的写法去跑一遍"** ——
所以**新写课时把提示词里的每条写法都真跑一次**，本身就是一次引擎体检。

## K. 第五轮更新（引擎控制流大修 + shell 课程补全）—— ✅ 完成

**起因**：并行写 shell 课的 agent 交回一份诚实报告 —— 任务书要求教的
`while IFS= read -r`、`case`、`$#` 参数校验、`2>&1` 顺序**在引擎里全都跑不通**，
那节课只能退化成"遍历手写字面量列表"，并写了一段"本站不支持"的免责说明。
顺着查下去，发现**站内三个命令条目都写着"管道里的 while 在子 shell 中执行"这个陷阱，
而引擎的实际行为和它们正好相反**（教材说输出 0，终端输出 3）。

| # | 项 | 做了什么 |
| --- | --- | --- |
| **K1** | **算术展开 `$(( ))` 不可用** | `maskBlocks` 把 `$((` 内层的 `(` 也屏蔽成 NUL，下游再也认不出算术展开，把它当"命令替换，命令是 `(2+3)`"执行 → `echo $((2+3))` 静默输出空行、`i=$((i+1))` 清空计数器。现已整块保留；`extractSubs` 同步不再误吞 |
| **K2** | **`[ ]` 数字比较恒真/恒假** | 两个独立缺陷：`testTokenize` 不把 `-` 当词边界（argv 到达时已是 `['1 -lt 2']`）；双目操作数**取反了**（`a = toks[p+1]` 拿到运算符）→ `[ "$A" = web ]` 恒假、`[ 1 -lt 2 ]` 恒真。**两者都不报错** |
| **K3** | **`A && B \|\| C` 少打印一行** | A 失败时 `break` 了整个语句列表；真 shell 是 `(A && B) \|\| C`，C 必须执行。`false && echo yes \|\| echo no` 原先什么都不打印 |
| **K4** | **`while read … done < file` 一次都不执行** | 执行器无条件把继承来的 stdin 抹成 `null`（`= cmdStdin ? {…} : null`），`read` 立刻返回 1 |
| **K5** | **`for i in $(seq 1 3)` 迭代出 `$(seq`/`1`/`3)`** | 词表在解析阶段就被按空格切开；改为保留原文、执行时先跑命令替换再按 IFS（含换行）切词 |
| **K6** | **`case` 把待匹配的词当命令执行** | `ctrlRunCase` 拿 `_execCommand(ctrl.word)` 的 stdout 当词用 → `bash: abc: command not found`，而分支照样匹配（"半对"最骗人）。另修 `ctrlParseCase` 吞掉 `esac` 之后所有语句 |
| **K7** | **循环体里不能嵌 `if`** | 循环体按 `{cmd,op}` 逐条执行，而 `if…then…fi` 天然跨多条 → `bash: if: command not found`。抽出 `ctrlParseList()` 按语句数组递归解析 |
| **K8** | **管道接控制流不可用** | `… \| while read` 在 `splitByAnd` 阶段就被循环体里的 `;` 切成三段。新增 `splitPipedControl()` + `_execScript` 的 `pipeFromPrev` 接线 |
| **K9** | **管道里的循环不在子 shell 里（教材一致性问题）** | 按真 shell 语义给多段管道与"管道接控制流"用**变量表副本**执行，退出即还原；单条命令不受影响 |
| **K10** | **`ls \| wc -l` 恒等于 1** | 真 `ls` 会看 stdout 是不是终端；引擎一律按列把名字拼成**一行**。新增 `ctx.tty`（由"是否管道非末段 / 是否有输出重定向"决定），并支持 `ls -1` |
| **K11** | **`> 文件 2>&1` 丢 stderr** | 合并只在 `_execOne` 最后做一次，而文件早写完了；改为写文件时就带上 stderr |
| **K12** | **`> out 2> err` 把 `>` 当参数传给命令** | `extractRedirect` 只剥末尾一个重定向，`> out` 因此留在命令行里变成参数（还报 `ls: cannot access '>'`）。改为循环剥离、按序全部应用 |
| **K13** | **`X=$(cmd \| awk …)` 报括号不配对、变量静默为空** | 切管道不屏蔽 `$( )` 内部，替换式里的 `\|` 被当外层管道。新增 `maskSubInteriors()`，**只给切分用** |

1. **aapt2 打不开中文路径** —— 项目目录 `E:\云计算-DS` 让它报 `failed to open directory`。
   → 检测到非 ASCII 路径就改在 `%TEMP%` 下构建。
2. **aapt2 把 assets 条目名写成反斜杠** —— 产出 `assets/www\index.html`，而 APK 是 ZIP，
   名字必须是 `/`，否则 `file:///android_asset/...` 解析不到，**装上就是白屏**。
   → 重打包时统一替换，并加断言。**这个坑是自检抓出来的，不是肉眼看出来的。**
3. **Node 20 起不能直接 spawn `.bat`** —— `d8.bat` 报 `EINVAL`。
   → 直接调背后的 `d8.jar` / `apksigner.jar`。

### J 的验证边界（诚实记录）

### I4 为什么值得单独说：静默的错误结果比报错危险一个数量级

上面 7 个"静默"缺陷的共同形态是：**命令成功退出、输出看着合理、结论是错的。**

| 缺陷 | 学员会得出什么错误结论 |
| --- | --- |
| `find -name` 失效 | "日志文件到处都是"（其实是把 README.md、app.jar 全列出来了） |
| `sort -h` 按字典序 | "这个目录不大"（8.0K 排在 5.9G 前面） |
| `cat` 把报错当内容 | "文件里就写着这行字"（其实是 `No such file or directory`） |
| `find -perm` 被丢弃 | "系统里到处是 SUID 程序"（其实一个都没有） |
| `sed` 地址范围静默为空 | "没匹配到"（其实真机是有输出的） |

**它们不会让任何测试变红，只会让人学到错的东西。**
所以修完之后，凡是"不认识的输入"一律改成**明确报错**（find 的未知选项、sed 的未知脚本写法），
宁可打断学员，也不要让他带着错误结论继续往下走。

### H1 手机版的判据（为什么不能只做"响应式堆叠"）

手机上如果照搬桌面布局堆叠，终端会吃掉固定高度、讲义只剩几十像素 —— **看得见终端、看不见讲义**。

实测数据（375×667，iPhone SE）：

| | 改造前 | 改造后 |
| --- | --- | --- |
| 讲义面板 | 332px | 358px |
| **讲义正文可视高度** | **49px**（头图 92 + 步骤条 85 把正文挤没） | **172px** |
| 终端 | 253px，与视口底差 6px | 227px，与视口底齐平 |
| 运行/复制按钮 | 26px 高 | 40px |
| 快捷键条 | 无（`\|` `~` `$` 和方向键在手机上敲不出来） | 13 个按钮，38px 高 |
| 输入框字号 | 12.5px（iOS 聚焦会放大整页） | 16px |

> ⚠️ **当时所有断言都是绿的** —— 因为断言量的是「讲义面板 ≥200px」。面板 332px 达标，
> 而正文只剩 49px。**断言量错了对象**。改成量正文可视高度之后才卡住这个回归。

- **改完必跑五套测试**：`validate-data` / `shell-check` / `render-check` / `lab-check` / `card-check`
