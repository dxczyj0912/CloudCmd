# 正式发布验收

源码已建立 Git 基线，自动化检查由 `.github/workflows/check.yml` 在推送和 PR 时运行。网站仍保持双击 `index.html` 离线可用。

1. 提交前运行 `node tools/check-all.js`，确认全部通过。
2. 由仓库外的长期保存的签名凭证提供 `CLOUDCMD_KEYSTORE`、`CLOUDCMD_KEY_ALIAS`、`CLOUDCMD_KEYSTORE_PASS`、`CLOUDCMD_KEY_PASS`；不要把私钥或密码提交进仓库。用递增的 `--version-code` 和对应 `--version-name` 构建。**不要用临时新密钥签正式包**，否则以后无法覆盖升级。
3. 运行 `node tools/release-check.js --apk=CloudCmd-版本.apk`，确认内容一致、全站检查通过、APK 签名有效。保存 APK 的 SHA-256 与 Git 提交号。
4. 在一台已安装上一版的 Android 真机上覆盖安装签名包，再在一台全新设备上安装。检查：首页启动、离线课程、站外链接、横竖屏、中文输入法弹出时终端输入行可见；升级前后进度、收藏、复习记录保留。
5. 用首页或练习页的“进度备份”导出 JSON，在另一浏览器或设备导入，确认课程、步骤、收藏与每日一练记录恢复；测试坏 JSON 被拒绝。
6. 用键盘走通首页搜索、练习模式、步骤运行、进度备份；用系统大字号和屏幕阅读器检查标题、按钮与状态提示。

没有可用的长期签名凭证或在线真机时，第 2～4 步保持待验状态，不能将未签名 APK 标为可安装正式版。
