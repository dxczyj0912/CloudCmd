# 03A · VPC、子网和安全组连通性

前置：完成[独立云主机部署](03-云主机部署.md)，并有[实验资源台账](00-云账号与成本边界.md)。本项目用两台**新建测试机**验证同 VPC 私网通信、子网、路由和安全组；不修改正在提供同步服务的服务器。参考[腾讯云 VPC 文档](https://cloud.tencent.com/document/product/215)与[云服务器文档](https://cloud.tencent.com/document/product/213)。

## 逐步操作

1. 在一个测试 VPC 内建立子网 A、B，CIDR 不重叠。保留第 03 关的测试机 A；在子网 B 创建短时运行的小规格测试机 B。记下两台机器的**私网 IP**、子网和安全组 ID。
2. 在 A 上确认网络事实：`ip -4 addr`、`ip route`、`ss -lntp`。在 B 上执行 `ip route get <A的私网IP>`，先预测流量走哪张网卡和网关。
3. 在 A 的空目录放一个无敏感信息的 `index.html`，用 `python3 -m http.server 18791 --bind 0.0.0.0` 临时监听。A 的安全组仅允许**来自 B 私网 IP**的 TCP 18791；若系统防火墙也启用，同样只允许此来源。
4. 在 B 上执行 `curl -i --max-time 5 http://<A的私网IP>:18791/`，应返回刚写的内容。从不在允许范围内的测试来源请求，应无法连接。再暂时撤回 A 对 B 的允许规则，观察连接失败；恢复规则后再次成功。
5. 对比“服务没监听”“系统防火墙拒绝”“安全组拒绝”“路由走错”四类证据：A 的 `ss`、两边的 `ip route`、B 的 `curl` 错误以及云控制台规则。不要仅凭 `ping` 成败判断 HTTP 是否可用。

## 验收与收尾

交付网络图、两次成功和一次失败的连通性记录、规则前后差异、排障判断。停止 A 上的临时 HTTP 服务，撤回临时安全组规则，释放测试机 B，并更新资源台账。删除子网或 VPC 前确认没有第 03 关的测试机及其他资源依赖。
