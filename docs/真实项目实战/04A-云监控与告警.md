# 04A · 云监控、告警和恢复通知

前置：[独立云主机部署](03-云主机部署.md)与[云账号和费用台账](00-云账号与成本边界.md)。本项目只使用隔离测试机，练“指标异常 → 告警 → 定位 → 恢复通知”。参考[腾讯云监控文档](https://cloud.tencent.com/document/product/248)。

## 逐步操作

1. 在控制台查看测试机的 CPU、内存、磁盘和公网流量指标。记录采样间隔、最近一个小时的正常基线以及实例 ID；确认监控能定位到**正确实例和区域**。
2. 新建仅作用于这台测试机的 CPU 告警策略。阈值略高于正常基线，持续时间至少覆盖两次采样；配置你能收到的通知渠道和自动恢复通知。记录阈值、统计周期及策略 ID。
3. 在测试机上执行一个**有明确超时**的 CPU 负载实验，例如先安装 `stress-ng`，再运行 `stress-ng --cpu 1 --timeout 420s --metrics-brief`。如果实例 CPU 核数较多或阈值不适合，先调整告警阈值，不增加无限时负载。
4. 观察 CPU 指标上升和告警触发时间；保存告警内容、实例 ID、指标窗口。到时自动停压，确认 CPU 回落、告警恢复通知到达。监控采样和通知存在延迟，不要把“命令退出”当成“已恢复”。
5. 额外检查应用健康：在本机通过第 03 关的 SSH 隧道请求 `/api/health`，记录应用层 200 与主机层 CPU 告警分别回答什么问题。写下若云监控正常但应用 502，下一步要查哪些日志和端口。

## 验收与收尾

交付正常基线、告警策略、触发与恢复时间线、应用健康结果和一次误报风险分析。删除只为实验创建的策略，核对测试机上没有遗留负载进程。仅看到告警策略“已创建”不算完成。
