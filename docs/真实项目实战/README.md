# 云计算真实项目实战：初级到中级

这条路线从 CloudCmd 这个真实 Web 服务出发，再接入云资源、Gitea、Online Boutique、OpenTelemetry 和 Argo CD。前半段训练初级云计算的资源、网络、存储、服务和监控能力；后半段用多服务故障、IaC 和 GitOps 训练中级实操。模拟终端可以预习，但通关只认真实环境的操作与恢复证据。

**项目性质要看清：**J1–J9 是围绕同一个 CloudCmd 服务展开的连续运维任务，不是九个不同的开源项目；M1、M3、M5 使用公开的完整应用，M2、M4、M6 是围绕它们完成的基础设施、发布和故障切换项目。下方另有 Ceph、OpenStack 两个资源要求更高的选修项目。核心路线为 J0–J9 + M1–M6，共 16 关；选修不计入中级通关条件。

## 怎么使用

1. 在仓库根目录执行本地实验命令。01、02、04、05 以 **PowerShell** 为准；03 区分本机 PowerShell 和云主机 Bash。云项目以产品官方文档和实际控制台为准。
2. 每项先核对准备条件，只在独立实验环境运行。`cloudcmd-lab`、18787～18791 端口与现有服务器分开；云资源要在 J0 的台账中登记。
3. 按“验收”检查真实结果；没有达到判据时先排障，不因为命令退出码是 0 就打勾。
4. 将环境、实际命令、结果、时间、回滚方式填进 [真实环境验收模板](../真实环境验收模板.json)，用 `node tools/real-lab-check.js --manifest=你的清单.json` 做格式检查。检查器只读清单，不执行实验命令。

每一关建议保留三样东西：**运行证据**（脱敏输出或截图）、**问题记录**（遇到什么、怎么定位）、**恢复证明**（重启、回滚或清理后再次验证）。不要把同步码、云密钥、私钥、个人进度或未脱敏日志提交到 Git。

这是一条可操作的学习路线，不承诺覆盖不同云厂商和发行版的所有差异。云资源、Docker、Kubernetes 的步骤以执行时的官方文档和实际版本为准；发现差异就记录到实验报告，再修订本路线。更详细的验收边界见[真实环境验收](../真实环境验收.md)。本机已实际验证 J1 的服务与数据重启，J2 的 Compose 配置已解析；其余项目的真实执行需要独立实验环境，当前不能标为通过。M3–M5 不建议与现有 4 GB 云服务器上的同步服务混跑。
