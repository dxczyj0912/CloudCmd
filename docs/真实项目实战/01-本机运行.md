# 01 · 本机运行与健康检查

目标：把 CloudCmd 当作一个真实 Web 服务运行，确认网页和 API 可访问，并验证测试同步数据在重启后保留。**以下命令在仓库根目录的 PowerShell 中执行**，不会连接线上服务器。

## 准备

- 已安装 Node.js 22 或项目支持的更新版本；执行 `node --version` 应显示版本号。
- 本机 18787 端口空闲。若已占用，请为本实验选另一个端口，并同步替换下文 URL。
- 打开两个 PowerShell 窗口，均进入本仓库根目录。

## 操作

在**窗口 A**设置独立端口与数据目录，再启动服务：

```powershell
node --version
$env:PORT = '18787'
$env:HOST = '127.0.0.1'
$env:CLOUDCMD_DATA_DIR = Join-Path $env:TEMP 'cloudcmd-lab-01-data'
node server.js
```

窗口应显示 `CloudCmd 已启动` 和测试数据路径，保持窗口 A 运行。在**窗口 B**检查健康接口与网页：

```powershell
Invoke-RestMethod http://127.0.0.1:18787/api/health
(Invoke-WebRequest http://127.0.0.1:18787/).StatusCode
```

第一条应返回 `ok: true`、`service: cloudcmd`，第二条应为 `200`。浏览器打开 `http://127.0.0.1:18787/`，确认能看到首页。

创建一个**只用于实验**的空同步会话，保存返回的同步码（不要截图或提交同步码）：

```powershell
$session = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:18787/api/sync/sessions -ContentType 'application/json' -Body '{"state":{}}'
$session.code
$session.revision
```

返回应有同步码和 `revision: 1`。在窗口 A 按 `Ctrl+C` 停止，再重新执行 `node server.js`。窗口 B 用刚才的 `$session.code` 查询：

```powershell
$saved = Invoke-RestMethod "http://127.0.0.1:18787/api/sync/sessions/$($session.code)"
$saved.code -eq $session.code
$saved.revision
```

布尔值应为 `True`，版本仍至少为 `1`；这说明测试数据不是只保存在进程内存里。

## 验收与收尾

记录 Node 版本、两个 HTTP 结果、重启前后的会话版本和实际数据目录。停止窗口 A 的服务。实验数据留在 Windows 临时目录 `cloudcmd-lab-01-data`，确认不再需要后可从资源管理器手动清理。下一关会换成独立 Docker 卷，不会使用这个目录。

若健康检查不通，先看窗口 A 是否仍在运行，再用 `Get-NetTCPConnection -LocalPort 18787 -ErrorAction SilentlyContinue` 查看端口是否被其他进程占用。若重启后同步码失效，核对两次启动是否使用同一个 `CLOUDCMD_DATA_DIR`，以及目录中是否存在 `sync-sessions.json`。
