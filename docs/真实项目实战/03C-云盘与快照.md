# 03C · 云硬盘挂载、快照与恢复

前置：[独立云主机部署](03-云主机部署.md)与[实验资源台账](00-云账号与成本边界.md)。只在**新建测试数据盘**操作，绝不对系统盘或已有业务盘运行格式化。参考[腾讯云 CBS 文档](https://cloud.tencent.com/document/product/362)。

## 逐步操作

1. 在与第 03 关测试机相同的可用区创建一块小容量测试云硬盘。记录磁盘 ID、容量、可用区、计费方式，再挂载到测试机。
2. 在测试机执行 `lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,UUID` 和 `sudo blkid`。把云控制台的磁盘 ID、容量与新出现的设备对应起来；若无法唯一确认设备，停止实验。
3. 仅对确认无数据的新盘创建文件系统，挂载到单独目录 `/mnt/cloudcmd-lab-disk`。写入 `lab-proof.txt`，记录其 SHA-256、挂载信息和 UUID。`fstab` 用 UUID 配置，再执行 `sudo mount -a` 和 `findmnt /mnt/cloudcmd-lab-disk` 验证重启前配置正确。
4. 在写入停止且文件系统状态一致时创建快照，记录快照 ID 和时间。用该快照**新建另一块测试盘**，挂到同一测试机的不同设备和目录；以只读方式挂载恢复盘，核对 `lab-proof.txt` 的 SHA-256。不要把恢复盘直接覆盖原盘。
5. 故意比较原盘与恢复盘的设备名、UUID 和数据。如果是整盘克隆，两个文件系统 UUID 可能相同；同时挂载时要用明确设备和只读选项，不能依赖含糊的 UUID 自动挂载。

## 验收与收尾

### 逐条命令与检查点（测试机 Bash）

以下示例假设新盘在系统中显示为 `/dev/vdb`、快照恢复盘为 `/dev/vdc`，**这只是示例**。先用云控制台磁盘 ID、容量与 `lsblk` 三方核对，再把 `DISK`、`RESTORED_DISK` 改成真实设备；不确定就停，绝不对系统盘执行 `mkfs`。

1. **确认设备身份：**

   ```bash
   lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,MOUNTPOINT,UUID
   findmnt /
   DISK=/dev/vdb  # 仅在控制台与 lsblk 都确认后修改
   lsblk -f "$DISK"
   ```

   **检查：**`DISK` 是新建的空盘，无文件系统、无挂载点，容量与控制台一致；任何一项不符立即停止。
2. **创建文件系统、挂载并写入证据：**

   ```bash
   sudo mkfs.ext4 "$DISK"
   sudo mkdir -p /mnt/cloudcmd-lab-disk
   sudo mount "$DISK" /mnt/cloudcmd-lab-disk
   printf 'cloudcmd-disk-proof\n' | sudo tee /mnt/cloudcmd-lab-disk/lab-proof.txt >/dev/null
   sha256sum /mnt/cloudcmd-lab-disk/lab-proof.txt
   findmnt /mnt/cloudcmd-lab-disk
   sudo blkid "$DISK"
   ```

   **检查：**摘要非空，`findmnt` 指向新盘。将 `blkid` 的真实 UUID 写入测试机 `/etc/fstab` 的**独立一行**后，先 `sudo umount /mnt/cloudcmd-lab-disk`，再 `sudo mount -a` 和 `findmnt /mnt/cloudcmd-lab-disk`；失败立刻恢复刚写的 fstab 行，不重启机器。
3. **做一致性快照：**

   ```bash
   sudo sync
   sudo umount /mnt/cloudcmd-lab-disk
   findmnt /mnt/cloudcmd-lab-disk || true
   ```

   **检查：**挂载点已卸载。此时在控制台对**核对过 ID 的实验盘**创建快照，记录快照 ID；再从快照创建**另一块**测试盘并挂载。创建快照期间不要向原盘写入。
4. **只读核对恢复盘：**

   ```bash
   lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,MOUNTPOINT,UUID
   RESTORED_DISK=/dev/vdc  # 仅在控制台和 lsblk 都确认后修改
   sudo mkdir -p /mnt/cloudcmd-lab-restore
   sudo mount -o ro "$RESTORED_DISK" /mnt/cloudcmd-lab-restore
   sha256sum /mnt/cloudcmd-lab-restore/lab-proof.txt
   findmnt /mnt/cloudcmd-lab-restore
   ```

   **检查：**摘要与第 2 步一致，恢复盘挂载选项含 `ro`。若克隆盘与原盘 UUID 相同，不用 UUID 自动挂载恢复盘；先清理测试 fstab 行，再按**明确设备**卸载和释放。

交付磁盘 ID ↔ Linux 设备的对应记录、挂载与 `fstab` 验证、快照 ID、恢复盘上的摘要一致性证据。卸载两块盘，移除测试 `fstab` 行，核对目标资源 ID 后释放恢复盘、原盘和快照；按实际计费规则确认账单不再增长。格式化或删除前始终重新核对设备和资源 ID。
