# 04 · 备份恢复与故障演练

目标：从第 2 关的实验卷备份同步数据，在**另一个 Compose 项目**恢复，证明备份确实可用。只操作 `cloudcmd-lab` 和 `cloudcmd-recovery` 两个实验项目；**以下命令在仓库根目录的 PowerShell 中执行**。

## 准备

Docker 已启动，18788 端口空闲。若第 2 关的实验卷还在，继续使用；若没有，先按第 2 关完成一次启动和会话创建。恢复用的第二个项目也要占用 18788，因此两个项目不能同时运行。

## 备份并记录验证用同步码

```powershell
docker compose -p cloudcmd-lab -f docs/真实项目实战/files/compose.lab.yml up -d
$session = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:18788/api/sync/sessions -ContentType 'application/json' -Body '{"state":{}}'
$code = $session.code
Invoke-RestMethod "http://127.0.0.1:18788/api/sync/sessions/$code"
docker compose -p cloudcmd-lab -f docs/真实项目实战/files/compose.lab.yml stop
$cid = docker compose -p cloudcmd-lab -f docs/真实项目实战/files/compose.lab.yml ps -a -q cloudcmd
$backup = Join-Path $env:TEMP 'cloudcmd-lab-sync-backup.json'
docker cp "${cid}:/data/sync-sessions.json" $backup
Get-FileHash $backup -Algorithm SHA256
```

`$cid` 应非空，`$backup` 文件应存在。此备份含实验同步码，**不要提交到仓库或分享**。停止容器后再复制，可避免复制过程中恰好发生写入。

## 在新环境恢复

先启动一个**全新**的 `cloudcmd-recovery` 项目，它有自己的空卷。旧同步码此时应该查不到：

```powershell
docker compose -p cloudcmd-recovery -f docs/真实项目实战/files/compose.lab.yml up -d
Invoke-RestMethod http://127.0.0.1:18788/api/health
```

在浏览器打开 `http://127.0.0.1:18788/api/sync/sessions/你的测试同步码` 应显示 404；或者用 PowerShell `try { Invoke-RestMethod "http://127.0.0.1:18788/api/sync/sessions/$code" } catch { $_.Exception.Response.StatusCode }` 观察 404。确认新环境是空的，再停机恢复文件：

```powershell
docker compose -p cloudcmd-recovery -f docs/真实项目实战/files/compose.lab.yml stop
$recoveryCid = docker compose -p cloudcmd-recovery -f docs/真实项目实战/files/compose.lab.yml ps -a -q cloudcmd
docker cp $backup "${recoveryCid}:/data/sync-sessions.json"
docker compose -p cloudcmd-recovery -f docs/真实项目实战/files/compose.lab.yml start
Invoke-RestMethod "http://127.0.0.1:18788/api/sync/sessions/$code"
```

最后一条应返回刚才的 `code` 和 `revision`。如果恢复后仍是 404，先核对 `$recoveryCid`、目标文件路径和容器日志；不要直接覆盖原实验卷。

## 验收与收尾

记录备份文件 SHA-256、恢复前的 404、恢复后的 200 与版本号，并写清楚恢复时曾停机。停止恢复项目：

```powershell
docker compose -p cloudcmd-recovery -f docs/真实项目实战/files/compose.lab.yml down
```

两个实验卷默认仍保留。确认实验结束且备份无需保留后，再手动清理对应卷和临时备份文件；先用 `docker volume ls` 核对**完整卷名**，不要执行面向所有卷的清理命令。真实生产备份还需要加密、异机保存、保留周期和定期恢复演练，本关只验证最小恢复闭环。
