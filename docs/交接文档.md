## 1. 这是什么

**CloudCmd（云计算命令手册）** —— 一个**零依赖、零构建、完全离线**的云计算学习站。

核心使用场景：**双击 `index.html` 就能用** —— 不需要服务器、不需要 `npm install`、不需要打包。这是项目的**立身之本**，所有技术选择都为它让路。

它包含四件事：

| 形态 | 说明 |
| --- | --- |
| **命令手册** | 18 个分类、830 条命令记录（语法/参数/示例/注意事项） |
| **实时练习平台** | 190 节练习课、775 个步骤（主站 188/764 + 内置网络课 2/11），每步都在**模拟终端**里真跑 |
| **每日一练** | 398 张卡片，简化版 SM-2 间隔重复 |
| **知识库** | 概念 67 / 报错 92 / 版本差异 43 / 认证对照 5 |

外加：**9 阶段学习路线图**、**37 条故障排查剧本**、**3 节跨分类综合实战**、**Android APK**（2.25 MB、零权限、完全离线）。

### 三种交付形态

```
index.html          主站：手册 + 搜索 + 路线图 + 故障速查 + 每日一练 + 临时 Shell 窗口
academy-lab.html    练习平台：左模拟终端 + 右步骤讲义（主站的练习列表整页跳到这里）
CloudCmd-1.2.apk    Android：把上面两个页面塞进 WebView，离线可用
```

## 2. 五分钟跑起来

### 方式一：直接双击（推荐，也是设计目标）

```
双击 index.html
```

`file://` 下必须能用 —— 所以项目**没有** ES Module、**没有** `fetch(json)`，数据全部通过传统 `<script>` 注入全局变量。

### 方式二：本地 HTTP（想看某节课 / 分享链接时方便）

```bash
node tools/serve.js 8899
```

然后打开 `http://127.0.0.1:8899/index.html`。
`file://` 的长路径很难贴给别人，这个零依赖静态服务器就是为这个场景写的（只监听 `127.0.0.1`）。

### 方式三：装到手机

`CloudCmd-1.2.apk` 直接安装。**零权限**、完全离线。

### 验证环境是否正常

```bash
node tools/check-all.js
```

应当输出 **`19 通过 / 0 失败 / 0 跳过`**（约 25 秒，其中 `lab-check` 占 16 秒 —— 它要启无头 Chrome）。

## 3. 十条不可违反的硬约束

> 这十条每一条都是**被踩出来的**，不是风格偏好。违反它们会立刻打破某些已验证的行为。

| # | 约束 | 为什么 |
| --- | --- | --- |
| 1 | **不加 npm 依赖、不加构建步骤** | `file://` 双击可用是立身之本。引入 bundler 就毁了它 |
| 2 | **不用 ES Module、不用 `fetch(json)`** | `file://` 下会被 CORS 拦死。数据必须走 `<script>` 注入 |
| 3 | **只用 ES5 语法** | 不经过任何转译。箭头函数、`const/let`、模板字符串、可选链都不能用 |
| 4 | **`CC_SHELL.extend()` 只加不覆盖** | 注册一个已存在的命令名是**静默无操作**（踩过两次：`gzip`、重复的 `java`）。要改已有命令只能改 `shell.js` 本体 |
| 5 | **`CC_SHELL.fsAdd()` 是 first-wins** | 同一路径第二次注册会被忽略。夹具冲突时先注册的赢 |
| 6 | **练习的每个 step 必须退出码 0** | `shell-check` 会真的执行每一步。有的命令"正常就该返回非 0"（`kubectl diff`、`grep` 无匹配、`blkid` 裸盘）→ 用 `\|\| echo "（…）"` 兜底 |
| 7 | **`answer` 不能与某个 step 产生同样副作用** | 校验器先跑 steps 再跑 answer。step 已创建的资源，answer 再建必然报"已存在" → **answer 要选只读的那一步** |
| 8 | **`expect` 要照引擎的真实输出写** | 不能照"真机应该输出什么"想当然。`/proc/<PID>/wchan` 在本引擎返回 `ep_poll`（真机常见 `futex`） |
| 9 | **中文内容里不要用 ASCII 单引号** | 字符串用单引号包裹时，一个 ASCII `'` 会把它截断。**用中文书名号「」代替**。这个坑踩过多次 |
| 10 | **块注释里不要给路径加粗** | `**/etc/shadow**` 里的 `*/` 会**提前闭合块注释**，导致整个文件语法错误、浏览器白屏。踩过 4 次 |

### `window.CC_SHELL` 的接口

```js
CC_SHELL.create({hostname, ip, ...})  // 新建一个 shell 实例（实例级环境覆盖）
CC_SHELL.extend({ 命令名: fn })        // 注册新命令 —— ⚠️ 只加不覆盖
CC_SHELL.fsAdd({ '/path': {...} })     // 往虚拟 FS 加文件/目录 —— ⚠️ first-wins
CC_SHELL.util                          // ok/fail/resolvePath/parentOf/baseName/
                                       // findNode/readFileOrErr/splitLines/
                                       // childrenSorted/expandLongOpts/pad/padLeft/
                                       // walkFiles/baseHost
CC_SHELL.commands                      // 已实现命令名数组（= 数据里能跑的那些）
CC_SHELL.cmds                          // 原始 CMDS 表
CC_SHELL.notImplemented / notImplementedReason(name)
CC_SHELL.runnable(name)                // 这条命令在模拟终端里跑得了吗
```

**命令函数的签名**（所有 `cmd-*.js` 都长这样）：

```js
CMDS.命令名 = function (argv, ctx, stdin, HOST) {
  // argv  : 参数数组（已去引号），argv[0] 通常是子命令
  // ctx   : { root, cwd, env, host, prevCwd, shell, err, code, tty }
  // stdin : 上一条命令的输出行数组（管道用），没接管道时是 null
  // HOST  : 本实例的机器环境（网卡/网关/DNS 一律从这读，不要写死）
  return ok(['第一行', '第二行']);            // 退出码 0
  // return fail(['error: 出错了']);          // 退出码 1，走 stderr
  // return { out: [...], err: [...], code: 2 };  // 自定义退出码
};
```

### 脚本加载顺序（**很重要**）

`index.html` 与 `academy-lab.html` 都是**按序加载**，顺序不能乱：

```
① data/*.js        全部数据（分类 → 卡片 → 虚拟环境 → 课程 → 知识库）
② store.js         状态封装
③ shell.js         引擎本体（必须先于所有 cmd-*.js）
④ cmd-*.js         命令模块（它们调 CC_SHELL.extend，依赖 ③ 已完成）
⑤ render/terminal/drill/router/app   视图与入口
```

**加一个新的 `cmd-*.js` 必须同时改两个 HTML 的 `<script>` 列表。**

## 5. 数据：三种内容面

三种内容**彼此独立、各有各的校验器**。理解这个分工是理解整个项目的关键：

| 内容面 | 文件 | 数量 | 校验器 | 用户看到它的地方 |
| --- | --- | --- | --- | --- |
| **命令记录** | `data/<分类>.js` | 830 | `validate-data` `example-check` | 分类页、搜索、详情页 |
| **练习课** | `data/lessons-*.js` | 188 节 / 764 步 | `shell-check` `hint-check` `about-leak-check` | 练习平台 |
| **卡片** | `data/cards*.js` | 398 | `card-check` | 每日一练 |

**三者通过 id 互相引用**，这就是项目的"连贯性链条"（六个环节**全部有校验器盯着**）：

```
路线图 ──prereq──► 阶段 ──catIds──► 分类
                                     │
课程 ──steps[].ref──────────────────► 命令记录
  │                                    │
  └──lesson─────────────────────► 卡片 ──cmdIds──┘
                                     │
故障剧本 ──cmdIds───────────────────┘
  └──kind: 'recipe'（中文名条目）
```

### 命令记录的字段（`data/<分类>.js`）

```js
{
  id: 'dk-ps',                  // 必填，前缀按分类固定（dk- / k8s- / lb- …）
  name: 'docker ps',
  alias: ['列出容器'],
  level: 1,                     // 1~4，决定"这节课算多难"
  syntax: 'docker ps [选项]',
  summary: '一句话',            // 有长度要求
  desc: '详细说明',
  params: [{ flag: '-a', desc: '…' }],
  examples: [{ cmd: 'docker ps -a', desc: '…' }],   // 首例最好能跑
  notes: ['…'],
  related: ['dk-images'],       // 必须指向真实存在的 id
  docs: 'https://…',
  tags: ['容器']
}
```

### 练习课的字段（`data/lessons-*.js`）

```js
{
  id: 'cap-incident-chain',
  cat: 'monitor',               // 主要归属分类
  title: '【综合实战】一次线上变慢',
  prompt: '现象描述（学员一开始看到的东西）',
  task: '本节要做什么',
  steps: [
    { title: '第一步', about: '这一步在干什么',   // ⚠️ about 不许写出命令名
      cmd: 'uptime',                             // ⚠️ 必须退出码 0
      ref: 'mo-top',                             // ⚠️ 必须指向真实记录（可跨分类）
      hint: ['概念提示（不许出现命令名）', '命令骨架（必须有 ____）'],
      note: '结论/判据' }
  ],
  answer: 'uptime && free -h',   // ⚠️ 要只读，且输出要匹配 expect
  alt: ['…'],                    // 备用答案，同样要能跑且匹配 expect
  expect: /load average|Mem:/,   // ⚠️ 照引擎真实输出写
  teach: '课后讲解（这里写"为什么"，可以很长）'
}
```

**四个校验器对每节课逐条检查**：

| 校验器 | 查什么 |
| --- | --- |
| `shell-check` | `answer` / 每个 `alt` / **每一步 `cmd`** 都能跑，且 `answer`+`alt` 的输出匹配 `expect`；每步退出码 0 |
| `hint-check` | 每步恰好两级 `hint`；第 2 级是骨架（含 `____`）且与 `cmd` 结构一致；**概念提示不许出现命令名** |
| `about-leak-check` | `about` 不许把命令写出来（不剧透） |
| `wire-continuity` | `steps[].ref` 指向真实记录；阶段 `prereq` 完整 |

## 6. 引擎的边界（最重要的知识）

**引擎实现的是命令的子集，而且不只是"少了几个命令"—— 很多命令实现了、但某些参数被悄悄忽略。**

这是本项目最需要传承的一条经验。写课前**必须**先看这一节。

### 6.1 你只能教"引擎跑得出来"的东西

```js
window.CC_SHELL.runnable('kubectl')   // 命令名在不在
```

**但 `runnable()` 只回答命令名，不回答参数。** 参数级差异**必须靠实测**。

### 6.2 已知的参数级限制（写课前必查）

| 命令 | 被忽略/不支持的部分 | 症状（**看起来很正常**） |
| --- | --- | --- |
| `awk` | `END` 块**不做算术、不支持 `printf`** | 错误率算不出来，`printf` 打印空值 |
| `sed` | 范围 `/起/,/止/` 只认**整串子串**，转义斜杠不生效 | range 恒返回 0 行 |
| `git log` | `--grep` / `--author` / `-- <file>` / `<rev>..<rev>` **全被忽略** | 返回全量日志，"筛选"无效 |
| `kubectl` | **不支持 `-o json`**（返回表格）；`logs -n` 的**选项顺序**有要求 | jq 管道报 `Cannot parse as JSON` |
| `mysql` | **不装载业务表行数据**（只支持 `SHOW` / 元数据查询） | `SELECT … FROM orders` 直接报错 |
| `redis-cli` | `LATENCY` 未实现 | 提示里提到它会把学员带进死路 |
| `helm` | `create/dependency/package/push` 只有教学说明；`--version` 被忽略 | 只能用 8 个子命令写课 |
| `keepalived` | **配置文件根本不存在** | 那条记录的示例跑不了 |
| `xargs` | 自己的选项**只在命令名之前**解析（已修） | — |

### 6.3 为什么"参数被静默忽略"比"命令未实现"危险一个数量级

- **命令未实现** → 报 `command not found`，学员**立刻知道**自己敲错了
- **参数被忽略** → **输出看起来完全正常**，只有对照"这条命令本该输出什么"才能发现

**它会同时污染教材**：如果 `expect` 也是照"看起来正常的输出"写的，
那这个错误就被固化进课程里了（`expect` 与实现**在两边都不算错**的情况下对不上）。

### 6.4 写课流程（固定三步，不要跳过）

```
① 查：引擎是否支持该命令**与该参数**（不只是命令名）
② 跑：把每一步的命令**真跑一遍**，把真实输出写进 expect
③ 兜：node tools/check-all.js 守住回归
```

**第 ② 步是硬要求。** 本项目最近一轮的 **8 个引擎缺陷全部是这样抓到的**：

- `helm template --set image.tag=X` 被夹具 tag 静默覆盖
- `helm status --revision N` **静默返回最新版**
- `xargs` 把子命令的 `-p` 当成自己的 `--interactive` 吃掉
- `/etc/hosts` 缺 `cache-prod-01` 与 `broker1~3` —— **11 条记录 + 全部 Kafka 示例此前一律跑不了**

一个省事的做法：把待写的命令攒成一个小 JSON，用一个临时脚本一次性跑完并打印
`code / out / err` —— 比在浏览器终端里一条条敲快得多，也不会看漏 stderr。

### 6.5 不要为了"看起来完整"去实现这些命令

引擎对 **73 个未实现命令逐条登记了拒绝理由**（`CC_SHELL.notImplementedReason(name)`）：

- `lsattr` / `getfacl` / `ethtool`：**读了只能返回空或编造**，属于"假装成功"
- `useradd` / `passwd` / `iptables` / `chattr`：**会写真实系统或安全边界**
- `at` / `cron`：**没有守护进程**，提交了也不会跑

**"诚实地说不支持"比"假装支持"更有教学价值。** 这条与"检查器不许说假话"是同一条原则。

## 7. 五个最常见任务的配方

### 配方 1：加一条命令记录

```
① 找到对应分类文件（data/<分类>.js），在数组里加一个对象（字段见 §5）
② 若该命令的首例要能跑 → 确认引擎支持它（§6）
③ node tools/validate-data.js    # 字段完整性 / id 唯一 / related 断链
④ node tools/check-all.js
```

**注意**：`related` 必须指向真实 id，`id` 前缀要按分类约定。

### 配方 2：加一节练习课

**不要手工往数组里拼 —— 用合并器**（它负责风格复刻与逗号归一化）：

```bash
# ① 写一个片段文件（普通 CommonJS 模块，正则可以正常写）
#    例如 tools/_new.js：
#    module.exports = [ { id:'…', cat:'…', steps:[…], answer:'…', alt:[…], expect:/…/, teach:'…' } ]

# ② 合并进目标文件
node tools/_merge-lessons.js tools/_new.js data/lessons-linux.js

# ③ 跑四道校验器
node tools/hint-check.js && node tools/about-leak-check.js
node tools/wire-continuity.js && node tools/shell-check.js
```

**为什么必须用合并器**：项目的 `hint-check` / `about-leak-check` / `wire-continuity`
都是**按行正则**扫描的，它们假定"一个步骤 = 一行、字段顺序是 title → about → cmd → ref → hint → note"。
手工拼很容易写成多行对象或双引号键 —— **语法没问题、站点也能渲染，但三个校验器一个步骤都扫不到**
（课程数涨了、步骤数纹丝不动）。踩过两次。

**要删一节课**：

```bash
node tools/_drop-lesson.js data/lessons-linux.js <课程id>
```

### 配方 3：加一个命令模块（`cmd-*.js`）

```js
/* assets/js/cmd-新组.js */
(function () {
  'use strict';
  if (!window.CC_SHELL || !window.CC_SHELL.extend) return;
  var U = window.CC_SHELL.util;
  window.CC_SHELL.extend({
    '新命令': function (argv, ctx, stdin, HOST) { return U.ok(['…']); }
  });
})();
```

**然后必须**：
1. 在两个 HTML 的 `<script>` 列表里加上它（**在 `shell.js` 之后**）
2. 在 `tools/_cmdlist.js` 里加上它（否则所有 Node 侧检查器都看不到这个命令）
3. **⚠️ 命令名不能与 `CMDS` 里已有的重复** —— `extend` 只加不覆盖，重复是静默无操作

### 配方 4：加一个分类

```bash
node tools/wire-phase2.js     # 一次搞定"注册表 + 数据文件"两处接线（幂等）
```

然后补 `data/<新分类>.js`、在 `data/lessons-*.js` 里加课、在 `data/roadmap.js` 里挂到某个阶段。

### 配方 5：改完重建 APK

```bash
node tools/build-apk.js
```

**改了 `assets/` 或 `data/` 里的任何文件都要重建** —— APK 里的站内文件是构建时快照，
不同步重建 `apk-check` 会红。**这是预期内的红，不是缺陷。**

## 11. 已知缺口与下一步

### 明确可做的（按价值排序）

**① 41 条"排查链路"记录从没被写成课** ⭐ 最高价值

那 175 条"非命令条目"里，**112 条的首例命令其实能跑**（它们是命令式变体，只是 `syntax` 首词与 `name` 不一致）。
其中 **89 条未被课教过**，而 **41 条的名字本身就是"链路/排查/流程/实战"** —— 它们天生就是课：

```
kubernetes   Pod 起不来排查三板斧 · Pending · CrashLoopBackOff · ImagePullBackOff · NotReady（各一条链路）
linux-net    端口不通 / 域名解析 / 网络慢（三条链路）· Connection refused 与 timed out 的区别
docker       容器反复重启 / 网络不通 / 时区不对 排查
security     后门排查 · AK/SK 泄露应急响应
cloud-cli    云上"端口不通"链路 · 成本排查 · 批量查 ECS 生成 SSH 清单
linux-storage 华为云 EVS 挂盘全流程 · LVM 在线扩容完整流程
```

**为什么值得做**：这些记录本来就是按"问题 → 步骤"组织的，变成课是**顺势而为**，不是硬造。

**② 约 10 条断言松到等于没断言**

26 节课的 `expect` 长度 < 12 字符或含 `.*`。逐条看过，约 10 条该收紧：

```
mon-load-vs-cores         /2|CPU/    ← answer 是 nproc，输出就一个 "2"
sh-param-fallback         /7/        ← 只查一个数字
sh-case-dispatch          /Web/      ← 单数词
```

其余是**有意的宽松**（`/LISTEN/`、`/deleted/`、`/REVISION/` 只关心关键词出现），**建议保留**。
**这件事的价值**：断言太松时，引擎改了行为它也不会红 —— 而这是本项目最在意的一类问题。

**③ 18 张卡的 `lesson` 关联跨了分类**

多数合理（`sec-*` 卡关联到 `cloud-cli` 的课），值得逐条确认。
与"19 张卡的关联没有 `cmdIds` 证据"是同一批历史遗留。

## 12. 踩过的坑（别重踩）

> 这一节是整份文档里**最省时间**的部分。每条都是真金白银换来的。

### 12.1 内容编码类

| 坑 | 表现 | 正确做法 |
| --- | --- | --- |
| **中文里的 ASCII 单引号** | 单引号字符串被截断，`syntax-check` 报错 | 用 `「」` 代替 |
| **块注释里给路径加粗** | `**/etc/shadow**` 的 `*/` 提前闭合注释 → 整文件语法错、**浏览器白屏** | 块注释里不要给路径加粗 |
| **`\u` 在字符串里** | `PS1='\u@\h'` 被当成 Unicode 转义 | 改述，或用 `\\u` |
| **正则里的未转义 `/`** | `expect: /a|/var/log/` → 正则字面量提前结束 | 避免，或转义成 `\/` |

### 12.2 数据装配类

| 坑 | 表现 | 正确做法 |
| --- | --- | --- |
| **数组尾逗号** | 追加记录变成 `},,` 或 `} {`。**踩过 4 次** | 用 `_merge-lessons.js`（自动归一化） |
| **全局替换不区分角色** | 同一个命令串出现在 `cmd` / `hint` 骨架 / `alt` 三处，替换把 `cmd` 一起改了。**踩过 3 次** | **先统计出现几次、分别是什么角色，再逐处改** |
| **正则被 `JSON.stringify` 化** | `expect` 变成 `{}`，`shell-check` 报 `l.expect.test is not a function`。**同一轮踩了两次** | 用 `_lesson-serialize.js`（它显式处理 RegExp） |
| **用 `replace` 做"在 X 之前插入"** | X 被顶掉（我曾经因此丢失一整行版本历史） | **先定位行号再 `splice`** |
| **批量重编号打到自己刚写入的东西** | 新增阶段用 `stage-3` 作 id，随后的"旧 stage-3→stage-5"规则把它也改了 | **新增与重编号分两步，新增的 id 先用占位符** |
| **`extend` 重复注册** | 静默无操作。踩过：`gzip`、重复的 `java` | 注册前先检查 `CC_SHELL.cmds[name]` |
| **`fsAdd` 路径冲突** | first-wins，第二次被忽略 | 注意注册顺序 |
| **备份文件放进 `data/`** | 被当作数据加载 → "id 重复"之类的怪错 | **临时文件放 `tools/`，不要放 `data/`** |

### 12.3 检查器自身的问题

| 坑 | 教训 |
| --- | --- |
| **一个会产生大量假阳性的检查器等于没有检查器** | `example-check` 第一次跑出 140 个"异常"，真死链只有 18 个 —— 那样的输出没人会看第二眼 |
| **过严的断言会把对的实现判成错的** | 我加过一条"入口课的 L1 步骤必须在前两步"，对全部 184 节课都查，把 `awk-topip` 这类**本来就从简单讲到复杂**的正常课全判成不合格 |
| **只查"容器存在"的断言等于没查** | 查 `id="cc-capstone"` 存在，内部循环没命中也通过 → 要查**渲染出的卡片数与内容** |
| **检查器的口径不一致** | `hint-check` 取 `cmd` 时不反转义、解析骨架时会 → 任何含反斜杠的命令都必然报"骨架不一致" |
| **测试环境是共享状态** | 破坏性示例会把夹具改走、误伤后面的示例。粒度实测选定"**每条命令记录一个 shell**"（38 → 32 → 48 三种里最优） |
| **断言写的是"语义上应该发生什么"而不是"引擎实际发生什么"** | 备用答案 `docker rmi $(…)` 看起来天经地义，但引擎没有真实删除行为 → 两边都不算错却对不上 |

### 12.4 工程环境类

| 坑 | 教训 |
| --- | --- |
| **`apk-check` 红 ≠ 你改坏了** | 改了 `assets/` 或 `data/` 不同步重建 APK 就会红。**先跑 `build-apk.js` 再判断** |
| **APK 的真实构建目录在 `%TEMP%`** | 项目目录名是中文，aapt2 按 ANSI 代码页解析路径会失败，所以 `build-apk.js` 在临时目录构建。**项目根的 `build-apk/` 是陈旧快照，别拿它判断包内内容** |
| **PowerShell 会吃掉 `$` 与中文引号** | 不要把含中文/`$`的 JS 用 `node -e "…"` 跑。**写到 `.ps1`/`.js` 文件里再跑**（且 `.ps1` 要纯 ASCII） |
| **`Select-Object -First N` 会截断上游管道** | 它会杀掉上游命令，导致 `[exit code: 1]` 的假失败 |
| **不要用 `Set-Content`/`Out-File` 写中文** | 编码会坏。用编辑工具或 `[IO.File]::WriteAllText` + UTF8 无 BOM |
| **无头浏览器的窗口尺寸 ≠ 视口尺寸** | 实测 800 的窗口得到 649 的视口。**布局断言要用注入式测量读 `getBoundingClientRect()`**，不要靠截图判断 |
| **验证要用真数据源，不要用缓存/派生物** | 我删过一个文件后用陈旧的 `build-apk/` 去确认，差点得出反的结论 |

## 13. 常见问题

**Q：我改了东西，怎么知道有没有坏？**
```bash
node tools/check-all.js        # 15 项，约 25 秒
```
改了 `assets/` 或 `data/` 的话，**先重建 APK** 再跑（否则 `apk-check` 必红）。

**Q：`apk-check` 红了，是我改坏了吗？**
先跑 `node tools/build-apk.js`。多数情况是"改了内容没重建"，那是预期内的红。

**Q：我加了一节课，但 `shell-check` 说"课程数"没变？**
多半是**风格没对齐** —— 校验器按行正则扫描，步骤必须是**一行**且字段顺序固定。
用 `tools/_merge-lessons.js` 合并，不要手工拼。

**Q：某个命令在终端里跑不了，我要实现它吗？**
先查 `CC_SHELL.notImplementedReason('命令名')`。**如果它已有拒绝理由，就不要实现** ——
本项目的原则是"诚实地说不支持，好过假装支持"。

**Q：我想加一个全新的分类？**
`node tools/wire-phase2.js` 一次搞定前两处接线，然后补数据文件、课程、路线图归属。

**Q：`tools/` 下那 150 多个 `_` 开头的文件能删吗？**
